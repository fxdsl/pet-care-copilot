## 2. 第五周架构

```text
PDF/MD/TXT 导入
  → Vue 选择文件并展示预览
  → Spring Boot KnowledgeController
  → FastAPI 提取/清洗/按页分块
  → 本地 FastEmbed + BGE 生成 512 维向量
  → Spring Boot + MyBatis 写入 MySQL

用户提问
  → Spring Boot 取得会话和宠物档案
  → Redis 读取最近 12 条上下文
       └─ 未命中/不可用 → MyBatis 回源 MySQL → 回填 Redis
  → MyBatis 读取当前 embedding 模型的候选分块
  → FastAPI BGE 查询向量 + 余弦相似度 Top-K
  → 有候选：大模型结构化判断“资料是否足以回答”
       ├─ 足够 → RAG 回答 + 真实文档/文件/页码来源
       └─ 不足 → 通用模型回答 + 明确路由标记 + 不展示伪来源
  → Spring Boot 同一事务保存 USER/ASSISTANT 消息
  → 事务提交后更新 Redis 最近上下文
```

MySQL 始终是会话和知识的事实来源，Redis 只是可丢失、可重建的加速层。

### 3.2 PDF 处理规则

- 最大文件大小：15 MiB。
- 最大页数：100 页。
- 最大提取正文：500,000 字符。
- 使用 `pypdf` 提取文字层，不执行外部命令。
- 加密 PDF、损坏 PDF、页数超限都会返回明确错误。
- 每页正文写入 `[PDF_PAGE:N]` 标记，分块时把 `pageStart/pageEnd` 一起保存。
- 全文去除空白后少于 20 个字符时返回 `OCR_REQUIRED`，不会写入知识库。

`OCR_REQUIRED` 表示文件主要是图片扫描件。目前完成的是扫描件识别和安全拦截，不会伪造 OCR 结果；文字型 PDF 已完整支持。后续若需要扫描件正文，可新增 PaddleOCR/Tesseract 服务，并继续复用本周的按页数据结构。

## 5. 两级混合路由

第五周不是简单地用相似度阈值决定是否回答，而是两级判断：

1. **本地检索门槛**：BGE 计算相似度，低于 `app.rag.min-score=0.35` 时不进入知识回答。
2. **模型可回答性判断**：有候选时，让 `qwen3.7-plus` 在同一次结构化调用中返回 `answerable` 与 `answer`。

路由结果：

| `stage` | `routingReason` | 行为 |
|---|---|---|
| `week-5-rag-llm` | `KNOWLEDGE_ANSWERABLE` | 知识足够，回答并展示真实来源 |
| `week-5-general-llm` | `NO_CANDIDATES` | 未达到检索门槛，调用通用模型，不展示来源 |
| `week-5-general-llm` | `MODEL_CONTEXT_INSUFFICIENT` | 有相似材料但不足以回答，改用通用模型，不展示来源 |
| `week-5-rag-local` | `KNOWLEDGE_MATCH_LOCAL_FALLBACK` | 没有 Key 时，根据命中知识做本地抽取式回答 |
| `week-5-rag-no-context` | 上述未命中原因 | 没有 Key 且知识不足，只返回安全兜底提示 |

这解决了“知识库找不到时不调用通用模型”和“相似但无关的文档被当成来源”两个问题。页面会显示路由原因与最高相关度，便于调试。

本次端到端实测：

- “幼猫一天应该喂几次？”进入 `week-5-rag-llm`，最高相关度约 77%，展示知识来源。
- “金毛洗澡多少钱？”已有候选但资料不足，进入 `week-5-general-llm`，`sources=[]`，原因是 `MODEL_CONTEXT_INSUFFICIENT`。
- “幼猫持续拒食并反复呕吐时怎么办？”命中 PDF 第 2 页，页面正确显示文件名和页码。

## 6. Redis 最近上下文缓存

### 6.1 缓存什么

Redis 不保存完整历史页面，也不再保存旧“会话摘要”。它只缓存下一轮模型需要的最近 12 条 USER/ASSISTANT 消息：

```text
Key: pet-assistant:conversation:context:{conversationId}:v1
TTL: 30 分钟
```

示例 Value：

```json
[
  {"role":"USER","content":"幼猫一天应该喂几次？"},
  {"role":"ASSISTANT","content":"可按月龄少量多餐……"},
  {"role":"USER","content":"如果它突然不吃呢？"}
]
```

不缓存 API Key、用户密码、知识向量、完整宠物档案或日志堆栈。日志只记录会话 ID、命中来源和故障回退，不输出消息正文。

### 6.2 读写策略

- 读取：先查 Redis；命中直接返回，未命中从 MySQL 查询最近 12 条并回填。
- 写入：本轮 USER 和 ASSISTANT 两条消息在 MySQL 事务成功提交后，再写最新上下文。
- 异常：Redis 连接失败、超时或缓存 JSON 损坏时按未命中处理，问答继续访问 MySQL。
- 一致性：事务回滚不会提前污染缓存。

点击左侧历史会话时，前端调用的是：

```http
GET /api/v1/conversations/{conversationId}/messages
```

这个接口仍从 MySQL 加载完整消息，因为 Redis 只有最近 12 条且可能过期。Redis 优化的是每次问答都需要的“模型上下文”，不是历史记录页面。

## 13. 核心代码讲解

### 13.1 BGE 模型为何延迟加载并区分 query/passage

代码位置：`ai-service/app/services/embedding_service.py` 的 `FastEmbedEmbeddingService`。

```python
@property
def model(self) -> TextEmbedding:
    if self._model is None:
        with self._lock:
            if self._model is None:
                self.cache_dir.mkdir(parents=True, exist_ok=True)
                extracted_model = self.cache_dir / (
                    f"fast-{self.model_name.rsplit('/', 1)[-1]}"
                )
                model_options = (
                    {"specific_model_path": str(extracted_model)}
                    if extracted_model.is_dir()
                    else {}
                )
                self._model = TextEmbedding(
                    model_name=self.model_name,
                    cache_dir=str(self.cache_dir),
                    **model_options,
                )
    return self._model
```

FastAPI 启动时不立即加载数百 MB 模型，第一次导入或检索才初始化。双重检查加线程锁避免两个并发请求重复加载。发现已解压缓存时传入 `specific_model_path`，以后离线启动不会先访问 Hugging Face。

知识正文使用 `passage_embed()`，用户问题使用 `query_embed()`：

```python
def embed_documents(self, texts: list[str]) -> list[list[float]]:
    return [
        self._normalize(vector.tolist())
        for vector in self.model.passage_embed(texts)
    ]

def embed_query(self, text: str) -> list[float]:
    vector = next(iter(self.model.query_embed([text])))
    return self._normalize(vector.tolist())
```

BGE 对“待检索正文”和“查询问题”的处理策略不同，混用会降低召回质量。调试模型加载时观察 `_model`、`extracted_model` 和输出维度；当前必须是 512。

### 13.2 PDF 为什么先预览再入库

代码位置：`ai-service/app/services/pdf_service.py` 的 `extract()`。

```python
for page_number, page in enumerate(reader.pages, start=1):
    text = self._clean_page_text(page.extract_text() or "")
    total_chars += len(text)
    pages.append(
        PdfPage(
            page_number=page_number,
            text=text,
            char_count=len(text),
        )
    )

meaningful_chars = len(
    re.sub(r"\s+", "", "".join(page.text for page in pages))
)
if meaningful_chars < self.MIN_EXTRACTED_CHARS:
    return PdfExtractResponse(
        status="OCR_REQUIRED",
        extraction_mode="SCANNED",
        content="",
        pages=pages,
        # ……其余展示字段
    )
```

解析接口是只读步骤：它先验证大小、PDF 结构、加密状态和页数，再逐页提取。有效文字少于 20 个时返回 `OCR_REQUIRED` 且 `content` 为空，前端不会允许把空扫描件写入知识库。

文字型 PDF 的正文会加入页标记：

```python
content = "\n\n".join(
    f"[PDF_PAGE:{page.page_number}]\n{page.text}"
    for page in pages
    if page.text
)
```

后续分块服务解析标记并把 `page_start/page_end` 存入 MySQL，所以答案页码来自确定性元数据，不是模型猜测。调试时依次观察 `page_count`、`meaningful_chars`、`status` 和 `content` 中的页标记。

### 13.3 Java 如何避免新旧向量并存

代码位置：`backend/business-service/src/main/java/com/petassistant/business/service/KnowledgeService.java`。

```java
private void replaceChunksWhenProcessingChanged(
        KnowledgeDocumentProjection existing,
        List<AiKnowledgeChunk> processedChunks,
        Instant now
) {
    String targetModel = processedChunks.get(0).embeddingModel();
    boolean unchanged = existing.chunkCount() == processedChunks.size()
            && existing.embeddedChunkCount() == existing.chunkCount()
            && targetModel.equals(existing.embeddingModel());
    if (unchanged) {
        return;
    }
    mapper.deleteChunksByDocumentId(existing.id());
    mapper.insertChunks(toEntities(existing.id(), processedChunks, now));
}
```

checksum 相同只能证明正文相同，不能证明向量仍然有效。模型名、分块数或向量完成度发生变化时，事务内先删除旧分块再插入新分块；异常会整体回滚。因此数据库里不会同时保留 hash 与 BGE 两套生产向量。

调试“重建后仍显示旧模型”时观察 `targetModel`、`existing.embeddingModel()`，并查询 `knowledge_chunk.embedding_model`。

### 13.4 两级混合路由如何作出决定

代码位置：`ai-service/app/services/rag_service.py` 的 `answer()`。

```python
selected = [
    item for item in ranked
    if item[1] >= request.min_score
][:request.top_k]

if not selected:
    return self._answer_without_context(request, reason, max_score)

decision = self._generate_with_answerability(request, selected)
if not decision.answerable:
    return RagResponse(
        answer="以下回答未命中可回答的本地知识资料……\n\n"
               + decision.answer,
        sources=[],
        stage="week-5-general-llm",
        routing_reason="MODEL_CONTEXT_INSUFFICIENT",
        max_score=self._rounded(max_score),
        # ……会话和模型字段
    )
```

第一层是确定性的相似度门槛；第二层是模型判断候选资料是否真的回答了问题。第二层返回 `false` 时必须清空 `sources`，否则页面会把“相似但不能回答”的文档误认为依据。

模型判断和最终答案合并为一次 JSON 调用，是为了节省免费额度：

```python
"只返回 JSON 对象："
"{\"answerable\":true或false,\"answer\":\"答案\"}。"
```

调试回答过短或路由异常时观察 `max_score`、`selected`、原始 JSON、`answerable` 和最终 `routing_reason`。例如提示词当前要求资料不足时给出“安全、简洁”的通用知识，因此兜底回答会比 RAG 回答短。

### 13.5 Redis Cache-Aside 的完整读写过程

```java

if (cached.isPresent()) {
    return tail(cached.get(), safeLimit);
}

requireConversation(conversationId);
List<ConversationContextMessage> context =
        mapper.findRecentMessages(conversationId, safeLimit).stream()
                .map(message -> new ConversationContextMessage(
                        message.role(), message.content()
                ))
                .toList();
contextCacheService.put(conversationId, context);

```

读取顺序是 Redis → MySQL → 回填 Redis。缓存层捕获连接和反序列化异常并返回 `Optional.empty()`，所以 Redis 宕机不会让问答失败。

写入发生在事务提交之后：

```java
public void putAfterCommit(
        String conversationId,
        List<ConversationContextMessage> messages
) {
    List<ConversationContextMessage> snapshot =
            List.copyOf(tail(messages, 12));
    afterCommit(() -> put(conversationId, snapshot));
}
```

先复制不可变快照，是为了避免事务结束前原列表被继续修改；`afterCommit` 保证回滚的消息不会进入缓存。调试时查看 Key `pet-assistant:conversation:context:{id}:v1`、TTL 和列表顺序。

原位置：`ai-service/app/services/rag_service.py`。下面保存被第六周整体替换的核心流程，便于对照“固定 RAG”如何演进成状态图；该代码已不在生产目录。

```python
"""第五周专业向量检索和两级混合路由（历史实现，已删除）。"""

class GenerationDecision(BaseModel):
    """模型结构化判断：资料是否足以回答，以及最终回答。"""

    answerable: bool
    answer: str = Field(min_length=1, max_length=4_000)


class RagService:
    """第五周固定 RAG：先排序候选，再在知识答案和通用答案之间二选一。"""

    def __init__(self, settings: Settings, embedding_service: EmbeddingProvider) -> None:
        self.settings = settings
        self.embedding_service = embedding_service

    def answer(self, request: RagRequest) -> RagResponse:
        query = self._build_query(request)
        query_vector = self.embedding_service.embed_query(query)
        ranked: list[tuple[RagCandidate, float]] = []
        for candidate in request.candidates:
            if candidate.embedding_model != self.embedding_service.model_name:
                continue
            score = self.embedding_service.cosine_similarity(
                query_vector, candidate.embedding
            )
            ranked.append((candidate, score))
        ranked.sort(key=lambda item: item[1], reverse=True)
        max_score = ranked[0][1] if ranked else None
        selected = [
            item for item in ranked if item[1] >= request.min_score
        ][: request.top_k]

        # 没有达到阈值的资料时，直接进入通用模型；没有 Key 则返回本地安全提示。
        if not selected:
            return self._answer_without_context(request, max_score)

        # 有候选时只调用一次结构化模型，让模型声明资料是否足以回答。
        if self.settings.llm_enabled:
            try:
                decision = self._generate_with_answerability(request, selected)
                if decision.answerable:
                    return self._rag_response(
                        request=request,
                        answer=decision.answer,
                        selected=selected,
                        max_score=max_score,
                        stage="week-5-rag-llm",
                        model_name=self.settings.llm_chat_model,
                        routing_reason="KNOWLEDGE_ANSWERABLE",
                    )
                return RagResponse(
                    answer=(
                        "以下回答未命中可回答的本地知识资料，由通用模型提供，仅供参考：\n\n"
                        + decision.answer
                    ),
                    conversation_id=request.conversation_id,
                    sources=[],
                    stage="week-5-general-llm",
                    model_name=self.settings.llm_chat_model,
                    routing_reason="MODEL_CONTEXT_INSUFFICIENT",
                    max_score=self._rounded(max_score),
                )
            except Exception as error:
                logger.warning("RAG generation failed: %s", type(error).__name__)

        # 未配置 Key 或模型失败时，从最高分分块抽取相邻句子。
        top_candidate = selected[0][0]
        return self._rag_response(
            request=request,
            answer=self._extractive_answer(request.question, top_candidate.content),
            selected=selected,
            max_score=max_score,
            stage="week-5-rag-local",
            model_name="local-extractive",
            routing_reason="LLM_UNAVAILABLE_LOCAL_EXTRACTIVE",
        )

    def _answer_without_context(
        self,
        request: RagRequest,
        max_score: float | None,
    ) -> RagResponse:
        if self.settings.llm_enabled:
            try:
                answer = self._generate_general_answer(request)
                return RagResponse(
                    answer=(
                        "以下回答未命中可回答的本地知识资料，由通用模型提供，仅供参考：\n\n"
                        + answer
                    ),
                    conversation_id=request.conversation_id,
                    sources=[],
                    stage="week-5-general-llm",
                    model_name=self.settings.llm_chat_model,
                    routing_reason="NO_KNOWLEDGE_CANDIDATE",
                    max_score=self._rounded(max_score),
                )
            except Exception as error:
                logger.warning("General answer failed: %s", type(error).__name__)
        return RagResponse(
            answer=(
                "当前知识库没有检索到足够相关的可靠资料，且通用模型当前不可用。"
                "请补充宠物类型、年龄、体重或症状持续时间；紧急情况请联系专业兽医。"
            ),
            conversation_id=request.conversation_id,
            sources=[],
            stage="week-5-local-no-context",
            model_name=None,
            routing_reason="NO_CONTEXT_AND_LLM_UNAVAILABLE",
            max_score=self._rounded(max_score),
        )

    def _generate_with_answerability(
        self,
        request: RagRequest,
        selected: list[tuple[RagCandidate, float]],
    ) -> GenerationDecision:
        context = "\n\n".join(
            f"[资料{index}｜{candidate.title}｜相关度{score:.2%}]\n{candidate.content}"
            for index, (candidate, score) in enumerate(selected, start=1)
        )
        messages = [{
            "role": "system",
            "content": (
                "判断给定资料是否足以直接回答宠物问题，只返回 JSON。"
                "格式为 {\"answerable\":boolean,\"answer\":string}。"
                "资料不足时 answerable=false，并给出有边界的通用建议。"
            ),
        }, {
            "role": "user",
            "content": f"问题：{request.question}\n\n资料：\n{context}",
        }]
        content = self._call_compatible_llm(messages, json_object=True)
        return GenerationDecision.model_validate_json(content)

    def _generate_general_answer(self, request: RagRequest) -> str:
        messages = [{
            "role": "system",
            "content": (
                "你是宠物日常养护助手。当前没有可采用的本地资料，"
                "请提供清晰、保守的通用建议，并说明需要补充的信息和就医边界。"
            ),
        }, {
            "role": "user",
            "content": request.question,
        }]
        return self._call_compatible_llm(messages, json_object=False)

    def _call_compatible_llm(
        self,
        messages: list[dict[str, str]],
        *,
        json_object: bool,
    ) -> str:
        payload: dict[str, object] = {
            "model": self.settings.llm_chat_model,
            "temperature": 0.2,
            "max_tokens": 1_200,
            "messages": messages,
        }
        if json_object:
            payload["response_format"] = {"type": "json_object"}
        if self.settings.is_bailian_compatible:
            payload["enable_thinking"] = False
        response = httpx.post(
            f"{self.settings.llm_base_url.rstrip('/')}/chat/completions",
            headers={"Authorization": f"Bearer {self.settings.llm_api_key}"},
            json=payload,
            timeout=self.settings.llm_timeout_seconds,
        )
        response.raise_for_status()
        return response.json()["choices"][0]["message"]["content"].strip()

    def _rag_response(
        self,
        request: RagRequest,
        answer: str,
        selected: list[tuple[RagCandidate, float]],
        max_score: float | None,
        stage: str,
        model_name: str,
        routing_reason: str,
    ) -> RagResponse:
        return RagResponse(
            answer=answer,
            conversation_id=request.conversation_id,
            sources=[self._source(candidate, score) for candidate, score in selected],
            stage=stage,
            model_name=model_name,
            routing_reason=routing_reason,
            max_score=self._rounded(max_score),
        )
```

这段历史实现的主要限制是：控制流固定、不能读取档案工具、无法对重复工具调用熔断，也没有逐节点执行摘要。第六周没有在旧类上叠加兼容判断，而是删除旧服务并建立显式状态图。

### 15.4 为什么只放进文档、不放进 `archive` 源码包

如果旧类仍以 `.py` 或 `.java` 留在源码树，IDE 自动补全、组件扫描或未来维护者都可能再次引用它，形成两套协议。文档代码块不会被编译和导入，既能保留学习轨迹，又满足“生产目录不保留老旧代码”的约定。
