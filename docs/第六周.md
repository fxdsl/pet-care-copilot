# 第六周：LangGraph 受控 ReAct Agent

## 1. 本周目标与完成情况

第六周把第五周固定的“两级 RAG 路由”升级为显式 Agent 状态图，同时保留 MySQL、MyBatis、Redis、多轮会话、宠物档案、专业中文向量和 PDF 来源能力。

- [x] FastAPI 使用 `langgraph==1.2.9` 构建 `reason → tool → reason` 循环。
- [x] 白名单只允许 `search_pet_knowledge`、`read_pet_profile` 两个进程内只读工具。
- [x] 最多 3 次工具调用、2 次连续工具异常、12 层图递归，并拦截完全重复调用。
- [x] 模型决策采用 JSON Object，不要求、不保存、不返回隐藏思维过程。
- [x] Vue 展示脱敏步骤、工具次数、终止原因和真实知识来源。
- [x] Java 继续使用标准 `controller/service/client/config/data/mapper` 分层与 MyBatis XML。
- [x] 第五周旧 `RagService`、`AiRag*` DTO 和 `/api/v1/rag/answer` 已从生产代码删除。
- [x] Python 10 项、Java 16 项自动化测试通过；Vue 生产构建通过。

LangGraph 官方文档强调循环图必须通过条件边进入 `END`，并可在调用时设置 `recursion_limit`；项目同时使用更小的业务工具上限，避免仅依赖框架最后保险。参考：[Graph API](https://docs.langchain.com/oss/python/langgraph/use-graph-api)、[GRAPH_RECURSION_LIMIT](https://docs.langchain.com/oss/python/langgraph/errors/GRAPH_RECURSION_LIMIT)、[LangGraph PyPI](https://pypi.org/project/langgraph/)。

## 2. 完整调用链

```text
Vue submitQuestion()
  ↓  POST Spring Boot 问答入口
ChatController.preview()
  ↓
ChatService.answer()  @Transactional
  ├─ 新问题：MySQL 创建会话；续问：Redis 读取最近 12 条，未命中回源 MySQL
  ├─ PetProfileService：只读取用户明确选择的档案
  ├─ KnowledgeMapper XML：MySQL 按宠物类型/分类读取有限候选
  └─ AiServiceClient：POST FastAPI Agent 入口
       ↓
PetAgentService / LangGraph
  reason ── final ──> finish ──> END
    │
    └─ tool ──> 白名单参数校验 ──> reason
                  ├─ search_pet_knowledge：本地 BGE 排序候选
                  └─ read_pet_profile：读取本轮已授权档案
       重复、异常、超限 ──> guard ──> END
  ↓
Java 保存 USER/ASSISTANT 到 MySQL，事务提交后刷新 Redis 最近上下文
  ↓
Vue 展示答案、来源、脱敏步骤、工具次数与终止原因
```

MySQL 仍是真实数据源。Redis 只保存模型所需的最近消息快照，历史会话页面仍从 MySQL 读取完整记录。第六周没有修改表结构，所以没有新增 Flyway 迁移。

## 4. Agent State

`AgentGraphState` 是节点之间唯一的显式共享状态，模型不能直接访问 Java 数据库或 Redis。

| 字段 | 类型 | 初始写入者 | 后续写入者 | 含义 |
|---|---|---|---|---|
| `request` | `AgentRequest` | `answer()` | 不修改 | 问题、历史、当前档案和 Java 授权候选 |
| `observations` | `list[str]` | `answer()` | `tool` | 给下一轮模型的有界工具观察 |
| `sources` | `list[AgentSource]` | `answer()` | `tool` | 工具真实命中的来源，不让模型伪造 |
| `steps` | `list[AgentStep]` | `answer()` | 所有节点 | 页面可展示的脱敏动作摘要 |
| `tool_signatures` | `list[str]` | `answer()` | `tool` | 工具名与稳定 JSON 参数签名，用于重复检测 |
| `tool_call_count` | `int` | `answer()` | `tool` | 已尝试的工具次数，包括被拦截和失败 |
| `consecutive_tool_errors` | `int` | `answer()` | `tool` | 连续失败次数；成功后清零 |
| `decision` | `AgentDecision?` | `answer()` | `reason` | 结构化 `tool` 或 `final` 决策 |
| `answer` | `str` | 无 | `finish/guard` | 最终返回正文 |
| `stage` | `str` | 无 | `finish/guard` | 当前处理路径 |
| `model_name` | `str?` | 无 | `finish/guard` | 实际模型名 |
| `routing_reason` | `str` | 无 | `finish/guard` | 面向排障的路由原因 |
| `termination_reason` | `str` | 无 | `reason/tool/finish/guard` | 图结束原因 |
| `guard_message` | `str` | 无 | 异常节点 | guard 的内部摘要，不含异常详情 |
| `max_score` | `float?` | `answer()` | `tool` | 多次检索中的最高相关度 |

一次正常状态变化示例：

```text
初始：tool_call_count=0, observations=[], sources=[]
reason：decision=search_pet_knowledge("幼猫喂养频率", 2)
tool：tool_call_count=1, observations=[KNOWLEDGE_FOUND...], sources=[chunk-1]
reason：decision=final(answer="建议少量多餐……")
finish：termination_reason=COMPLETED, stage=week-6-agent-rag
```

## 5. 节点、条件边与失败方式

| 节点 | 输入重点 | 输出重点 | 副作用 | 失败路径 |
|---|---|---|---|---|
| `reason` | request、最近观察、次数 | `AgentDecision`、步骤 | 一次百炼兼容调用 | JSON/网络错误进入 `MODEL_DECISION_ERROR` |
| `tool` | decision、request | 观察、来源、分数、次数 | 只执行进程内只读函数 | 重复进入 `REPEATED_TOOL_CALL`；连续错误进入 `TOOL_ERROR_LIMIT` |
| `finish` | final decision、sources | 答案、正常 stage | 无 | 无有效 final 不会路由到这里 |
| `guard` | termination_reason | 安全提示、阻断步骤 | 无 | 统一返回稳定响应，不抛 500 |
| `fallback` | request | 本地抽取答案/无上下文提示 | 本地 BGE | 仅在没有 API Key 时使用 |

终止条件：

1. 模型返回 `final`，进入 `finish`，原因 `COMPLETED`。
2. 已执行 3 次工具，原因 `TOOL_CALL_LIMIT`。
3. 相同工具名和完全相同参数再次出现，原因 `REPEATED_TOOL_CALL`。
4. 连续 2 次工具参数、白名单或执行错误，原因 `TOOL_ERROR_LIMIT`。
5. 模型请求/JSON 决策失败，原因 `MODEL_DECISION_ERROR`。
6. 图超过 12 层递归，捕获 `GraphRecursionError`，原因 `GRAPH_RECURSION_LIMIT`。

## 6. 工具白名单

### 6.1 `search_pet_knowledge`

参数模型：

| 参数 | 类型 | 必填 | 约束 | 含义 |
|---|---|---|---|---|
| `query` | string | 是 | 1～500 字符 | 用于本地 BGE query 向量的检索语句 |
| `top_k` | integer | 否 | 默认 3，1～3 | 最多返回的知识分块数 |

工具只能搜索 Java 已经按宠物类型与分类授权的候选，不能自行查询数据库。观察正文最多 5000 字符，每个候选正文最多取 1500 字符。

### 6.2 `read_pet_profile`

参数必须是空对象 `{}`，多余字段会被 Pydantic `extra="forbid"` 拒绝。它只能读取当前请求中的 `pet_profile`，不接受档案 ID，因此模型无法尝试读取其他用户档案。

白名单工具不能发邮件、写数据库、执行命令或访问任意 URL。未知工具名统一当作受控错误，页面只看到脱敏摘要。

### 7.1 Vue 如何接收 Agent 轨迹

代码位置：`frontend/src/App.vue` 的 `submitQuestion()`。


调试时观察：浏览器 Network 请求 Body、`response.agentSteps`、`conversationId.value` 和 `errorMessage.value`。

### 7.3 MyBatis 如何限制 Agent 可见知识

代码位置：`backend/business-service/src/main/resources/mapper/KnowledgeMapper.xml` 的 `findAgentCandidates`。

```xml
<select id="findAgentCandidates" resultMap="agentCandidateMap">
    SELECT c.id AS chunk_id, c.document_id, d.title, d.source_url,
           d.file_name, c.chunk_index, c.content,
           CAST(c.embedding_json AS CHAR) AS embedding_json,
           c.embedding_model, c.page_start, c.page_end
    FROM knowledge_chunk c
    INNER JOIN knowledge_document d ON d.id = c.document_id
    WHERE d.status = 'READY' AND c.embedding_json IS NOT NULL
    <if test="petType != null and petType != ''">
        AND d.pet_type = #{petType}
    </if>
    <if test="category != null and category != ''">
        AND d.category = #{category}
    </if>
    ORDER BY d.created_at DESC, c.chunk_index
    LIMIT #{limit}
</select>
```

执行过程：MySQL 先执行权限边界式粗筛，只返回 READY 且已有向量的分块；FastAPI 工具再做真正的余弦排序。SQL 参数全部使用 MyBatis 绑定，不拼接用户输入。

调试时观察：IDEA MyBatisX 可从 `findAgentCandidates` 跳到 XML；检查 `petType/category/limit` 和返回 `embeddingModel` 是否与当前 BGE 模型一致。

### 7.4 Java 到 FastAPI 的协议

代码位置：`backend/business-service/src/main/java/com/petassistant/business/client/AiServiceClient.java` 的 `answer()`。

```java
public AiAgentResponse answer(AiAgentRequest request) {
    try {
        AiAgentResponse response = aiRestClient.post()
                .uri("/api/v1/agent/answer")
                .body(request)
                .retrieve()
                .body(AiAgentResponse.class);
        if (response == null) {
            throw new IllegalStateException("AI 服务返回空响应");
        }
        return response;
    } catch (Exception error) {
        log.warn("Agent answer call failed: {}", error.toString());
        throw new AiServiceUnavailableException(error);
    }
}
```

执行过程：RestClient 基地址和超时集中配置；任何连接、超时、非成功状态或反序列化错误都转换成统一业务异常，浏览器收到 `502 AI_SERVICE_UNAVAILABLE`。

调试时观察：Java 控制台 `Agent answer call failed`、FastAPI 8000 端口健康状态、`AI_SERVICE_RESPONSE_TIMEOUT`。

### 7.5 LangGraph 的图与条件边

代码位置：`ai-service/app/services/agent_service.py` 的 `_build_graph()`。

```python
builder = StateGraph(AgentGraphState)
builder.add_node("reason", self._reason_node)
builder.add_node("tool", self._tool_node)
builder.add_node("finish", self._finish_node)
builder.add_node("guard", self._guard_node)
builder.add_edge(START, "reason")
builder.add_conditional_edges(
    "reason", self._route_after_reason,
    {"tool": "tool", "finish": "finish", "guard": "guard"},
)
builder.add_conditional_edges(
    "tool", self._route_after_tool,
    {"reason": "reason", "guard": "guard"},
)
builder.add_edge("finish", END)
builder.add_edge("guard", END)
```

执行过程：`reason` 只产生结构化决策；`tool` 只执行白名单函数；正常答案和受控异常从不同节点进入 `END`。条件边和普通边不混用，避免一个节点被意外执行两次。

调试时观察：`decision.action`、`termination_reason`、下一节点返回值，以及 `graph.invoke(..., {"recursion_limit": 12})`。

### 7.6 重复检测与连续异常熔断

代码位置：`agent_service.py` 的 `_tool_node()`。

```python
attempt_count = state.get("tool_call_count", 0) + 1
signature = self._tool_signature(decision.tool_name, decision.tool_arguments)
signatures = list(state.get("tool_signatures", []))
if signature in signatures:
    return {
        "tool_call_count": attempt_count,
        "termination_reason": "REPEATED_TOOL_CALL",
        "guard_message": "检测到完全相同的工具调用。",
        "steps": self._append_step(
            state, node="tool", action="EXECUTE_TOOL",
            tool_name=decision.tool_name, status="BLOCKED",
            summary="重复工具调用已被拦截，避免循环和 Token 浪费。",
        ),
    }
```

执行过程：签名使用工具名和按键排序后的 JSON 参数，因此只拦截“完全相同”的调用；换一个更精确的检索 query 仍可继续。工具错误不会直接暴露内部异常，第一次作为观察返回模型修正，连续第二次进入 guard。

调试时观察：`signature`、`tool_signatures`、`consecutive_tool_errors`、`tool_call_count`。

## 8. 完整接口参数字典

本周文档只出现三个 HTTP 接口，以下逐一列全参数。浏览器外部 JSON 使用驼峰，Java 到 FastAPI 内部 JSON 使用蛇形。

### 8.1 Spring Boot 问答接口

方法与路径：`POST /api/v1/chat/preview`  
调用方向：Vue → Spring Boot。  
Path 参数：无。Query 参数：无。

请求 Body：

| JSON 字段 | 类型 | 必填 | 默认/约束 | 含义 |
|---|---|---|---|---|
| `question` | string | 是 | 非空，最多 2000 字符 | 当前用户问题 |
| `conversationId` | string | 否 | `null`，最多 36 字符 | 空时创建随机 UUID 会话；有值时续接 |
| `petProfileId` | string | 否 | `null`，最多 36 字符 | 用户明确选择的档案 ID |
| `petType` | string | 否 | `null`，最多 30 字符 | 没选档案时的知识粗筛条件 |
| `category` | string | 否 | `null`，最多 50 字符 | 知识分类粗筛条件 |

成功状态 `200`，响应顶层：

| 字段 | 类型 | 可空 | 含义 |
|---|---|---|---|
| `answer` | string | 否 | Agent 最终答案或安全终止提示 |
| `conversationId` | string | 否 | Java 创建或复用的会话 UUID |
| `sources` | `SourceReference[]` | 否 | 工具真实采用的来源，可能为空数组 |
| `stage` | string | 否 | `week-6-agent-rag/general/guarded/local/local-no-context` 之一 |
| `modelName` | string | 是 | `qwen3.7-plus`、`local-extractive` 或空 |
| `routingReason` | string | 否 | 路由原因 |
| `maxScore` | number | 是 | 本轮知识检索最高余弦相关度 |
| `agentSteps` | `AgentStepResponse[]` | 否 | 脱敏步骤列表 |
| `terminationReason` | string | 否 | 正常、降级或熔断原因 |
| `toolCallCount` | integer | 否 | 本轮尝试的工具次数，0～3，重复拦截也计数 |

`SourceReference` 子字段：

| 字段 | 类型 | 可空 | 含义 |
|---|---|---|---|
| `title` | string | 否 | 文档标题 |
| `url` | string | 是 | 来源 URL |
| `chunkId` | string | 否 | MySQL 分块 ID |
| `score` | number | 否 | 余弦相关度 |
| `fileName` | string | 是 | 原 PDF/文本文件名 |
| `pageStart` | integer | 是 | 起始页 |
| `pageEnd` | integer | 是 | 结束页 |

`AgentStepResponse` 子字段：

| 字段 | 类型 | 可空 | 约束/含义 |
|---|---|---|---|
| `sequence` | integer | 否 | 从 1 连续编号 |
| `node` | string | 否 | `reason/tool/finish/guard/fallback` |
| `action` | string | 否 | 节点动作名 |
| `toolName` | string | 是 | 工具节点对应名称 |
| `status` | string | 否 | `SUCCESS/ERROR/BLOCKED` |
| `summary` | string | 否 | 最多 500 字符的脱敏摘要 |

错误响应固定为 `code:string`、`message:string`、`timestamp:ISO-8601 string`：

| HTTP | code | 触发条件 |
|---|---|---|
| 400 | `INVALID_REQUEST` | 空白问题、字段超长或业务参数错误 |
| 400 | `INVALID_JSON` | JSON 语法或字段类型错误 |
| 404 | `CONVERSATION_NOT_FOUND` | 传入的会话不存在 |
| 404 | `PET_PROFILE_NOT_FOUND` | 档案不存在 |
| 502 | `AI_SERVICE_UNAVAILABLE` | FastAPI 连接、超时或协议错误 |
| 503 | `DATABASE_UNAVAILABLE` | MySQL 读写失败 |
| 500 | `INTERNAL_ERROR` | 未预期 Java 异常 |

### 8.2 FastAPI Agent 内部接口

方法与路径：`POST /api/v1/agent/answer`  
调用方向：Spring Boot → FastAPI。  
Path 参数：无。Query 参数：无。

请求 Body 顶层：

| JSON 字段 | 类型 | 必填 | 默认/约束 | 含义 |
|---|---|---|---|---|
| `question` | string | 是 | 1～2000，去除首尾空格后不可为空 | 当前问题 |
| `conversation_id` | string | 否 | `null` | 会话 ID，仅用于响应关联 |
| `history` | `ConversationMessage[]` | 否 | `[]`，最多 20 条 | Java 提供的有限历史 |
| `pet_profile` | `PetProfileContext` | 否 | `null` | 当前明确选择的档案 |
| `candidates` | `AgentCandidate[]` | 否 | `[]`，最多 2000 条 | Java 授权给知识工具的候选 |
| `top_k` | integer | 否 | 默认 3，接口范围 1～10；工具实际最多 3 | Java 建议召回数 |
| `min_score` | number | 否 | Python 默认 0.08；Java 默认传 0.35；范围 -1～1 | 最低余弦分数 |

`ConversationMessage`：

| 字段 | 类型 | 必填 | 约束/含义 |
|---|---|---|---|
| `role` | string | 是 | `USER` 或 `ASSISTANT` |
| `content` | string | 是 | 1～4000 字符 |

`PetProfileContext`：

| 字段 | 类型 | 必填 | 约束/含义 |
|---|---|---|---|
| `name` | string | 是 | 1～80，宠物名 |
| `pet_type` | string | 是 | 1～30，宠物类型 |
| `breed` | string | 否 | 最多 100，品种 |
| `age_months` | integer | 否 | 0～600，月龄 |
| `weight_kg` | number | 否 | 大于 0 且不超过 9999.99 |
| `notes` | string | 否 | 最多 1000，用户备注 |

`AgentCandidate`：

| 字段 | 类型 | 必填 | 约束/含义 |
|---|---|---|---|
| `chunk_id` | string | 是 | 分块 ID |
| `document_id` | string | 是 | 文档 ID |
| `title` | string | 是 | 文档标题 |
| `source_name` | string | 否 | 来源名称 |
| `source_url` | string | 否 | 来源 URL |
| `chunk_index` | integer | 是 | 文档内分块序号 |
| `content` | string | 是 | 分块正文 |
| `embedding` | `number[]` | 是 | 至少 1 维；生产为 512 维 |
| `embedding_model` | string | 是 | 必须与当前工具模型一致才参与排序 |
| `file_name` | string | 否 | 原文件名 |
| `page_start` | integer | 否 | 起始页 |
| `page_end` | integer | 否 | 结束页 |

成功状态 `200`。响应使用蛇形，对应字段为：`answer:string`、`conversation_id:string?`、`sources:AgentSource[]`、`stage:string`、`model_name:string?`、`routing_reason:string`、`max_score:number?`、`agent_steps:AgentStep[]`、`termination_reason:string`、`tool_call_count:integer`。

`AgentSource`：`title:string`、`url:string?`、`chunk_id:string`、`score:number`、`file_name:string?`、`page_start:integer?`、`page_end:integer?`。  
`AgentStep`：`sequence:integer`、`node:reason|tool|finish|guard|fallback`、`action:string`、`tool_name:string?`、`status:SUCCESS|ERROR|BLOCKED`、`summary:string(最多500)`。

FastAPI 参数校验失败返回 `422`，响应为 `detail[]`，每项通常包含 `type`、`loc`、`msg`、`input`。受控工具异常和循环上限不返回 500，而是使用 `200` 加 `week-6-agent-guarded` 和明确 `termination_reason`。

## 9. 配置、API Key 与费用边界

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `DASHSCOPE_API_KEY` 或 `AI_LLM_API_KEY` | 空 | 百炼 Key；只放系统环境或本机 `.env` |
| `AI_LLM_CHAT_MODEL` | `qwen3.7-plus` | Agent 决策与回答模型 |
| `AI_LLM_BASE_URL` | 百炼北京兼容地址 | OpenAI 兼容入口 |
| `AI_LLM_TIMEOUT_SECONDS` | `20` | 单次模型调用超时 |
| `AI_AGENT_MAX_TOOL_CALLS` | `3` | 单轮工具尝试上限 |
| `AI_AGENT_MAX_CONSECUTIVE_ERRORS` | `2` | 连续工具异常熔断阈值 |
| `AI_AGENT_RECURSION_LIMIT` | `12` | LangGraph 最后递归保险 |
| `AI_AGENT_MAX_OBSERVATION_CHARS` | `5000` | 单次知识观察正文上限 |
| `AI_SERVICE_RESPONSE_TIMEOUT` | `35s` | Java 等待整个 Agent 回答的上限 |

本地 BGE 不消耗百炼额度。启用 Key 后，每经过一次 `reason` 都会调用一次百炼：通常“工具一次再回答”会调用模型 2 次，最多 3 次工具可能产生更多决策调用。因此工具上限、重复拦截和错误熔断既是稳定性措施，也是免费额度保护。测试强制清空真实 Key并使用替身，不会调用收费网络。

## 12. 常见问题

### 回答只出现本地抽取，没有 `qwen3.7-plus`

检查健康响应 `answer_mode`。若为 `agent-local-extractive`，说明启动 FastAPI 的进程没有读取到 Key。系统环境变量修改后需完全重启 Python 进程；不要把真实 Key 写进文档或提交文件。

### Java 返回 502

先直接检查 FastAPI 健康状态，再查看 Python 是否存在模型超时、JSON 决策无效或依赖未安装。Java 只会返回稳定错误，真实内部原因在两个服务控制台。

### 轨迹显示 `REPEATED_TOOL_CALL`

这不是服务器崩溃，而是模型连续请求了同名同参数工具。换一种更具体的问法；开发调试时检查第二次 decision 的 `tool_arguments`。

### 轨迹显示 `TOOL_ERROR_LIMIT`

通常是模型生成未知工具、参数多余或 `top_k` 超过 3。查看步骤工具名和 FastAPI warning 日志；日志不会打印完整敏感正文。

### 历史消息里没有旧的 Agent 轨迹

当前 MySQL `message` 表保存消息正文、模型名和 token 计数，不保存步骤。轨迹只随本轮实时响应展示；第六周没有为了轨迹修改历史表。需要长期审计时应新增独立执行表，而不是把步骤 JSON 混进消息正文。
