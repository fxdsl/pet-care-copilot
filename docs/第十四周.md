# 第十四周：模块化单体入口、稳定性、监控与可交付工程

> 完成日期：2026-08-27
> 架构简化：2026-08-28，默认改为模块化单体入口，Gateway 保留为可选储备
> 数据库：沿用 Flyway V11，本周无结构变更
> 核心技术：Nginx、Spring Boot、Resilience4j、Micrometer、Prometheus、Grafana、Docker Compose；Spring Cloud Gateway 作为后期拆分储备
> 部署说明：按项目所有者要求，本周只交付部署配置和教程，不代替用户启动或部署。实际运行验收由[项目部署教程](项目部署教程.md)逐步完成。

## 1. 本周完成结果

```text
浏览器
  → Nginx / 前端静态资源
      ├─ IP 基础限流
      ├─ 生成 X-Request-ID
      ├─ /api/** 直连 Business
      └─ /ws/** 直连 Business WebSocket
  → Business Service :8080（只在容器内网）
      ├─ JWT 最终验签与角色授权
      ├─ MyBatis + MySQL
      ├─ Redis / RabbitMQ / MinIO / OpenSearch
      └─ FastAPI Agent

Business Actuator
  → Prometheus 每 15 秒抓取
  → Grafana 自动加载数据源和项目总览 Dashboard

后期拆分：Nginx → Gateway :8088 → 多个业务服务
```

已完成：

- 默认链路保持模块化单体：本地 Vue 直连 Business，生产 Nginx 直连 Business。
- Nginx 为 `/api/**`、`/ws/**` 提供基础 IP 限流并生成请求编号；Spring Boot 继续负责 CORS、JWT 和精确业务限流。
- 独立 `backend/gateway-service` 代码和测试完整保留，但放入 Compose `microservices` profile，当前默认不启动。
- 后期启用 Gateway 时可使用 Redis Token Bucket 按令牌摘要或 IP 限流；网关不解析、不记录 JWT。
- 业务服务继续做最终 JWT 验签与角色授权，不能信任网关传来的用户字段。
- FastAPI、MinIO、RabbitMQ、OpenSearch 增加显式超时、熔断、隔离舱和受控重试。
- 修复 JWT Filter 把下游数据库异常误写成认证失败的问题。
- 日志使用 `requestId/userId/conversationId/eventId` 串联，正文、Token、手机号等不进入日志模板。
- Prometheus 指标覆盖 HTTP、JVM、熔断器、Outbox、RabbitMQ 积压、Agent 工具次数、估算 Token 和审核时长。
- 提供 Grafana 自动配置和总览 Dashboard。
- 提供四个应用 Dockerfile、Nginx 配置、10 个默认服务 + 1 个可选 Gateway 的 Compose、环境变量模板、持久卷和健康检查。
- 前端本机默认访问 `http://localhost:8080`；生产镜像使用同源 `/api` 直接代理 Business。

## 2. 工程分层与端口

| 组件 | 默认端口 | 是否应暴露公网 | 职责 |
|---|---:|---|---|
| Frontend/Nginx | 80 | 是（生产应再加 HTTPS） | 静态资源与反向代理 |
| Gateway（可选） | 8088 | 否；默认不启动 | 后期拆分服务时的统一路由与 Redis 令牌桶 |
| Business Service | 8080 | 否 | 权限和业务事实 |
| FastAPI | 8000 | 否 | Agent、本地向量和文档处理 |

Gateway 储备模块基于 Spring Boot 3.5.x 对应的 Spring Cloud 2025.0.x 发布列，依赖版本由 BOM 管理。当前 Business 模块没有引入 Spring Cloud，仍是标准 Spring Boot 模块化单体。

## 3. 核心代码讲解

### 3.1 后期拆分储备：Gateway 路由与令牌桶

```java
return builder.routes()
    .route("business-api", route -> route.path("/api/**")
        .filters(filters -> filters.requestRateLimiter(config -> config
            .setRateLimiter(apiRedisRateLimiter)
            .setKeyResolver(userOrIpKeyResolver)))
        .uri(businessServiceUri))
    .route("business-websocket", route -> route.path("/ws/**")
        .uri(webSocketUri(businessServiceUri)))
    .build();
```

这段代码当前不在默认链路。后期拆分时，登录用户的 Key 是 Bearer Token 的 SHA-256 截断摘要，匿名请求使用远端 IP。网关只做入口流量保护，不把摘要当身份，业务服务仍重新验签 JWT。

### 3.2 安全请求编号

```java
String supplied = request.getHeaders().getFirst("X-Request-ID");
String requestId = supplied != null && SAFE_ID.matcher(supplied).matches()
        ? supplied : UUID.randomUUID().toString();
response.getHeaders().set("X-Request-ID", requestId);
```

默认部署由 Nginx 的 `$request_id` 覆盖 `X-Request-ID`，业务服务再次校验并放入 MDC。保留的 Gateway Filter 同样只接受 8～80 位字母、数字和 `._:-`，阻止换行符污染日志。

### 3.3 Resilience4j 的重试边界

```java
@Retry(name = "rabbitPublisher")
@CircuitBreaker(name = "rabbitPublisher")
@Bulkhead(name = "rabbitPublisher", type = Bulkhead.Type.SEMAPHORE)
public void send(..., String eventId, String eventType) { ... }
```

RabbitMQ 只重试携带稳定 `eventId` 的 Outbox 消息，消费者用数据库主键幂等。普通非幂等写请求不能因为“网络异常”盲目重试；MinIO 预签名、搜索 PUT 固定文档 ID和本地向量生成属于可重复操作。

### 3.4 外部调用超时

```java
OkHttpClient client = new OkHttpClient.Builder()
        .connectTimeout(properties.connectTimeout())
        .readTimeout(properties.readTimeout())
        .build();
```

超时先于熔断：连接 MinIO 默认 2 秒，读取默认 5 秒；OpenSearch 同样有连接/读取超时；Java 等待 Agent 默认 35 秒。没有超时的熔断会让线程先耗尽，无法真正保护服务。

### 3.5 结构化关联日志

```text
ts=%date level=%level service=%property{spring.application.name}
requestId=%X{requestId} userId=%X{userId}
conversationId=%X{conversationId} eventId=%X{eventId}
logger=%logger msg="%replace(%msg){'[\r\n]+',' '}"
```

HTTP Filter、JWT Filter、问答 Service 和 RabbitMQ Consumer 分别写入对应 MDC 字段，并在 `finally` 中删除，避免线程复用导致串号。换行被替换，日志模板不输出 Header、Body 或异常对象中的密钥。

### 3.6 业务指标

```java
registry.counter("pet_agent_tool_calls_total").increment(toolCallCount);
registry.timer("pet_knowledge_review_latency").record(duration);
Gauge.builder("pet_queue_backlog_messages", value, AtomicLong::get)
        .tag("queue", queueName).register(registry);
```

指标标签只使用有限枚举/队列名，不使用 userId、conversationId 或问题正文，避免 Prometheus 高基数。FastAPI 尚未返回准确 usage，因此指标明确叫 `pet_ai_estimated_tokens_total`，不能拿它当百炼账单。

### 3.7 JWT Filter 异常边界

```java
try {
    authenticateToken(request);
} catch (AuthenticationException error) {
    writeUnauthorized(response);
    return;
}
filterChain.doFilter(request, response);
```

只捕获 Token 解析和用户校验异常。下游 Controller、MySQL 或 Redis 抛出的错误由全局异常处理器处理，不能再被误报为 `401 Token 无效`。

## 4. 默认 Nginx 与可选 Gateway 契约

本周不新增业务 JSON API；第十三周及以前的接口 Path、Query、Body 和响应结构均不变。默认部署中浏览器通过同源 Nginx 访问 Business，本地开发则直接访问 Business `8080`。

| 名称 | 方向 | 类型 | 必填 | 含义 |
|---|---|---|---|---|
| `Authorization` | 请求 | `Bearer <JWT>` | 受保护接口必填 | Nginx 透传，Business 最终验签 |
| `X-Request-ID` | 请求/响应 | string | 请求可选、响应必有 | Nginx 生成，Business 校验后写回响应 |
| `X-Gateway` | 响应 | string | 默认无 | 只有未来启用 Gateway 时才返回 `pet-assistant` |
| `X-RateLimit-*` | 响应 | string | 默认无 | 只有未来启用 Gateway Redis 令牌桶时才可能返回 |

默认 Nginx 以来源 IP 做每秒 20 次、突发 40 次的基础保护，超过后返回 `429 Too Many Requests`，不依赖 Redis。登录、验证码、问答等需要识别用户和业务动作的精确限制仍由 Spring Boot + Redis 负责。未来启用 Gateway 时，才使用保留的 Redis Token Bucket；业务内部可降级缓存仍按各周规则回源 MySQL。

### 4.1 健康与指标

| 方法与 Path | Body/Query | 响应 | 访问方式 |
|---|---|---|---|
| `GET /actuator/health` | 无 | `{"status":"UP"}` 或组件状态 | 默认仅 Business 容器内网端口 |
| `GET /actuator/health/liveness` | 无 | 存活状态 | Docker 健康检查 |
| `GET /actuator/health/readiness` | 无 | 就绪状态 | Docker 启动依赖 |
| `GET /actuator/prometheus` | 无 | Prometheus 文本格式 | 仅容器监控网络抓取 |
| `GET /actuator/gateway/routes` | 无 | Gateway 路由诊断 | 仅未来启动 Gateway 时存在 |

这些端点不接收业务参数。默认 Compose 不向主机暴露 Business `8080`，Nginx 只代理业务路径，不代理 Actuator；生产防火墙仍需限制 Prometheus 和 Grafana。

## 5. Resilience4j 策略表

| 实例 | 超时来源 | 重试 | 熔断 | 隔离 | 降级/补偿 |
|---|---|---|---|---|---|
| `aiService` | WebClient 2s/35s | 只对安全处理最多 2 次 | 20 次窗口，50% 失败开启 | 12 并发 | 问答返回 AI 暂不可用；事实不写半轮 |
| `minio` | OkHttp 2s/5s | 预签名最多 2 次 | 同默认 | 16 并发 | 上传准备失败可重试，不生成假 URL |
| `openSearchRead` | HTTP 2s/5s | 最多 2 次 | `openSearch` | 20 并发 | 同权限 MySQL 降级 |
| `openSearchWrite` | HTTP 2s/5s | 固定 `_id` 最多 3 次 | `openSearch` | 20 并发 | Outbox 保留并可全量重建 |
| `rabbitPublisher` | Rabbit 连接 3s | 稳定 eventId 最多 3 次 | 同默认 | 8 并发 | Outbox FAILED/人工处理 |

熔断默认：至少 10 次调用后统计、20 次滑动窗口、失败率 50%、慢调用 4 秒、Open 30 秒、Half-open 放 3 次探测。

## 6. Prometheus 指标与 Grafana

| 指标 | 类型 | 解释 |
|---|---|---|
| `http_server_requests_seconds_*` | Timer | QPS、延迟、状态码 |
| `resilience4j_circuitbreaker_*` | Gauge/Counter | 熔断状态与调用结果 |
| `pet_outbox_publish_total{result}` | Counter | Outbox 发布成功/失败 |
| `pet_queue_backlog_messages{queue}` | Gauge | Quartz 最近采样的 Rabbit 积压 |
| `pet_agent_tool_calls_total` | Counter | Agent 工具调用次数 |
| `pet_ai_estimated_tokens_total` | Counter | 估算字符换算量，不是账单 Token |
| `pet_knowledge_review_latency_seconds_*` | Timer | 投稿创建至完成审核的耗时 |
| JVM/进程指标 | Gauge | 内存、GC、线程、CPU |

Prometheus 默认每 15 秒只抓取 `business-service:8080`。Grafana provisioning 会自动创建 Prometheus 数据源并加载 `deploy/monitoring/grafana/dashboards/overview.json`。后期真正启用 Gateway 后，再为 `gateway:8088` 增加抓取任务，避免默认监控长期出现一个 `DOWN` 目标。

## 7. Docker Compose 交付物

| 文件 | 作用 |
|---|---|
| `deploy/docker-compose.full.yml` | 10 个默认服务、1 个可选 Gateway、持久卷、健康依赖 |
| `deploy/.env.deploy.example` | 不含真实秘密的配置模板 |
| `*/Dockerfile` | 多阶段构建 Java/Vue，Python 使用独立镜像 |
| `frontend/nginx.conf` | SPA fallback、同源 `/api`/`/ws` 代理和静态缓存 |
| `deploy/monitoring/prometheus.yml` | 抓取目标 |
| `deploy/monitoring/grafana/**` | 数据源和 Dashboard 自动配置 |

MySQL、Redis、RabbitMQ、MinIO、OpenSearch、Embedding 模型和监控都使用命名卷。删除容器不会删除卷；执行 `down -v` 会永久删除数据，教程明确禁止新手随意使用。

MinIO 使用 `pet-files.local` 解决“容器生成的 URL 浏览器无法解析”和“localhost 在容器内指向自己”的矛盾。本机学习需要 hosts 映射；生产需使用内外都能解析的真实域名并启用 HTTPS。

## 10. 故障矩阵

| 故障 | 用户表现 | 系统行为 | 恢复动作 |
|---|---|---|---|
| Redis 缓存故障 | 个别查询变慢，依赖 Redis 的精确限制不可用 | Nginx 基础 IP 限流继续工作；业务缓存和精确限制按既有安全规则处理 | 恢复 Redis，观察 health 和缓存重建 |
| RabbitMQ 故障 | 异步媒体/索引延迟 | Outbox 留存 FAILED | 恢复队列，运行补偿，检查人工队列 |
| OpenSearch 故障 | 页面显示 MySQL 安全降级 | 权限条件不放宽 | 恢复后执行全量重建 |
| MinIO 故障 | 上传/图片 URL 获取失败 | 不写假成功 | 恢复后重试，检查孤儿记录 |
| FastAPI/百炼故障 | 问答明确提示暂不可用 | 超时、隔离、熔断，事务不保存半轮 | 检查 Key/额度/网络和熔断状态 |
| MySQL 故障 | 业务不可写 | readiness 失败，依赖服务不应接流量 | 从备份恢复并让 Flyway 校验 |

完整部署、升级、备份和回滚步骤见[《项目部署教程》](项目部署教程.md)。
