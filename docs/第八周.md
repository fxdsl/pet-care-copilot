# 第八周：角色化门户、宠物社区发布、媒体与异步事件

## 1. 本周目标与完成结果

第八周不只是增加一个“社区页面”，还修复了第七周角色边界不清的问题，并为后续评论、推荐、知识共建和统一搜索建立可靠基础。

已完成：

- 管理员与普通用户使用不同导航、页面和后端接口权限。纯 `ADMIN` 不再进入普通智能问答、普通宠物档案和社区；`USER/VERIFIED_SELLER` 不能进入知识管理和管理员接口。
- 管理员可以分页检索用户、调整角色、禁用/恢复账号和查询审计日志；禁止降级自己、禁用自己或移除最后一个启用管理员。
- JWT 增加 `securityVersion`。每次鉴权以 MySQL 中的角色、状态和安全版本为准，角色/状态修改后旧访问令牌立即失效，并撤销该用户全部刷新令牌。
- 知识管理页增加管理员专用 RAG 测试，复用真实检索和 Agent 回答，但不创建普通会话、不写聊天消息。
- 普通用户可以创建草稿、编辑、发布、删除、查看自己的帖子和浏览公开帖子；编辑使用 `version` 乐观锁。
- 帖子可以关联自己的宠物档案、话题、地区和最多 6 个图片/短视频。
- 浏览器通过短期预签名 PUT 地址直传 MinIO；Java 先保存媒体所有者和期望元数据，上传后再按 MinIO 实际元数据确认。
- 业务表与事件表同一 MySQL 事务写入；定时发布器把 Outbox 事件投递 RabbitMQ，失败指数退避，媒体消费者幂等更新处理状态。
- 帖子详情使用 Redis Cache-Aside，浏览量写 Redis Hash 后由 Lua 原子取出并批量回写 MySQL，Redisson Bloom Filter 拦截明显不存在的 ID。
- 聚合健康检查新增 RabbitMQ 和 MinIO 状态；任一外部依赖故障不会伪装成业务服务自身故障。

本周没有实现评论、点赞、收藏和关注，响应中的相应计数字段先保持数据库默认值；这些能力属于第九周。

## 4. 数据库 V6

Flyway V6 已在本机真实 MySQL 8.0 成功执行，并且后续启动校验 6 个迁移全部通过。已执行的迁移文件不能再编辑，下一次表结构变化必须创建 V7。

### 4.1 `app_user.security_version`

`BIGINT NOT NULL DEFAULT 1`。角色或状态变化时 SQL 同时执行 `security_version = security_version + 1`。JWT 携带签发时版本，旧 JWT 的版本不再等于数据库版本，因此立即失效。

### 4.2 `admin_audit_log`

|---|---|
| `id` | 审计 UUID |
| `actor_user_id` | 执行管理员 |
| `target_user_id` | 被操作用户，可空 |

| `before_value/after_value` | 变更前后值 |

### 4.3 社区表

帖子状态允许 `DRAFT/PENDING_REVIEW/PUBLISHED/HIDDEN/DELETED`。本周用户流程实际使用 `DRAFT → PUBLISHED → DELETED`，待审核与隐藏将在第九周内容治理中启用。

## 5. 核心调用链与代码讲解

### 5.1 旧 JWT 如何立即失效

`JwtAuthenticationFilter` 解析签名后，把 `userId/role/securityVersion` 组成 `AuthenticatedUser`，随后调用：

```java
public boolean isCurrent(AuthenticatedUser principal) {
    UserEntity user = userMapper.findById(principal.userId());
    if (user == null) return false;
    SecuritySnapshot snapshot = new SecuritySnapshot(
            user.role(), user.status(), user.securityVersion()
    );
    writeCache(principal.userId(), snapshot);
    return "ACTIVE".equals(snapshot.status())
            && principal.role().equals(snapshot.role())
            && principal.securityVersion() == snapshot.securityVersion();
}
```

这里故意让 MySQL 参与每次安全决策，Redis 中的 `auth:principal:{userId}` 是短期观察快照，不是授权真相。这样即使 Redis 删除失败，也不会继续接受被撤权的 JWT；数据库不可用时返回 503，而不是沿用无法确认的旧权限。

### 5.2 管理员修改角色的事务边界

```java
@Transactional
public AdminUserResponse updateRole(String actorId, String targetId,
                                    UpdateUserRoleRequest request) {
    UserEntity actor = requireAdmin(actorId);
    UserEntity target = requireUser(targetId);
    String nextRole = request.role().toUpperCase(Locale.ROOT);
    if (actor.id().equals(target.id()) && !"ADMIN".equals(nextRole)) {
        throw new AdminOperationConflictException("不能撤销当前登录账号自己的管理员权限");
    }
    protectLastAdmin(target, nextRole, target.status());
    userMapper.updateRole(target.id(), nextRole, Instant.now());
    audit(actor.id(), target.id(), "USER_ROLE_CHANGED", target.role(), nextRole);
    invalidateAfterCommit(target.id());
    return toResponse(requireUser(target.id()));
}
```

顺序是：重新读取操作者 → 检查自操作和最后管理员 → 更新用户并递增安全版本 → 插入审计 → 事务提交后删除用户/权限缓存和撤销刷新令牌。`afterCommit` 避免数据库最终回滚时提前清掉有效会话。

### 5.3 帖子草稿、编辑与发布

```java
@Transactional
public CommunityPostResponse create(String userId, CreateCommunityPostRequest request) {
    validateRelations(userId, request.petProfileId(), request.topicId());
    List<String> mediaIds = normalizedMediaIds(request.mediaIds());
    String postId = UUID.randomUUID().toString();
    postMapper.insert(new CommunityPostEntity(
            postId, userId, blankToNull(request.petProfileId()),
            blankToNull(request.topicId()), request.title().trim(),
            request.content().trim(), blankToNull(request.region()),
            "DRAFT", 0, 0, 0, 0, 1, null, Instant.now(), Instant.now()
    ));
    replaceMedia(userId, postId, mediaIds);
    return requireOwnedResponse(userId, postId);
}
```

`petProfileId` 必须属于当前 JWT 用户；媒体必须已确认、未绑定且也属于当前用户。更新 SQL 同时包含 `id + author_id + expectedVersion`，返回 0 时给前端 `409 COMMUNITY_POST_CONFLICT`，防止两个页面用旧数据互相覆盖。

发布时先在 MySQL 把帖子设为 `PUBLISHED`，同一事务写 `POST_PUBLISHED` Outbox；提交后才对公众可见。RabbitMQ 暂停不会回滚已经合法发布的帖子，待恢复后 Outbox 会继续投递。

### 5.4 帖子 Cache-Aside、Bloom 和浏览量

详情顺序：Bloom 判空 → Redis `GET` → 未命中查询 MySQL → 回填详情 JSON → Redis Hash 浏览增量 `+1`。

```java
public CommunityPostResponse publicDetail(String postId) {
    if (!cache.mightExist(postId)) throw new CommunityPostNotFoundException();
    CommunityPostResponse response = cache.get(postId);
    if (response == null) {
        CommunityPostView view = postMapper.findPublicView(postId);
        if (view == null) throw new CommunityPostNotFoundException();
        response = toResponse(view);
        cache.put(response);
    }
    long pendingViews = cache.incrementView(postId);
    return withViewCount(response, response.viewCount() + pendingViews);
}
```

Bloom 的 `ready` 标记只有从 MySQL 全量装入发布 ID 后才设置。没有 ready、Redis 故障或 Redisson 故障时一律放行到 MySQL，避免合法帖子被误判不存在。Bloom 只做“肯定不存在”的快速判断，绝不替代数据库。

计数回写不能先读再删，否则并发增量会丢失。`CommunityCounterFlushService` 使用 Lua 原子取走字段：

```java
private static final DefaultRedisScript<Long> TAKE_DELTA = new DefaultRedisScript<>(
    "local value = redis.call('HGET', KEYS[1], ARGV[1]); "
  + "if not value then return 0 end; "
  + "redis.call('HDEL', KEYS[1], ARGV[1]); return tonumber(value)",
    Long.class
);
```

MySQL 回写失败时 Java 把取出的增量加回 Hash，并保留 dirty Set，10 秒后重试。帖子详情本身 Redis 故障时回源 MySQL；浏览计数暂时不能增加，但帖子仍可读。

### 5.5 MinIO 预签名上传

```java
public MediaUploadResponse createUpload(String userId, CreateMediaUploadRequest request) {
    String contentType = request.contentType().trim().toLowerCase(Locale.ROOT);
    String mediaType = resolveMediaType(contentType, request.sizeBytes());
    String mediaId = UUID.randomUUID().toString();
    String objectKey = "community/" + userId + "/" + mediaId + safeExtension(request.fileName());
    PresignedUrl upload = objectStorage.createUploadUrl(objectKey);
    mapper.insert(new CommunityMediaEntity(
            mediaId, userId, null, objectKey, request.fileName().trim(), mediaType,
            contentType, request.sizeBytes(), normalizeChecksum(request.checksumSha256()),
            "PENDING", "WAITING", Instant.now(), null
    ));
    return new MediaUploadResponse(mediaId, objectKey, upload.url(), "PUT", upload.expiresAt());
}
```

前端不是把大文件先传 Java，而是：申请地址 → `PUT uploadUrl` 直传 MinIO → 调用 confirm → 把 `mediaId` 放进帖子。确认时 Java 用 MinIO `stat` 比较实际大小和 Content-Type。只接受 JPEG/PNG/WebP（≤10 MiB）和 MP4/WebM（≤50 MiB）。

`checksumSha256` 本周已经持久化，但 MinIO 普通 ETag 不能等同于 SHA-256，因此暂不伪装成已完成的内容校验；后续异步处理读取对象流时再核对。

### 5.6 Outbox 与 RabbitMQ

```java
@Scheduled(fixedDelayString = "${app.community.outbox-publish-delay-ms:3000}")
@Transactional
public void publishDue() {
    for (OutboxEventEntity event : mapper.findDue(Instant.now(), 20)) {
        publishOne(event);
    }
}
```

发布器先用条件更新把事件从待处理状态认领为 `PROCESSING`，再投递交换机 `pet.community.events`。成功标记 `PUBLISHED`；失败按 2、4、8……最多 300 秒退避。消息带 `messageId=outboxId` 和 `eventType`，消费者只对 `MEDIA_CONFIRMED` 执行幂等状态更新。因此重复投递不会重复插入媒体。

第八周交付的是可重试、可幂等的媒体处理通道和 READY 状态闭环；真正的图片缩略图、视频转码与内容审核模型还需要额外处理器，将在后续内容治理阶段接入，文档不把“只改状态”误写成已经完成转码。

## 6. Redis Key 完整说明

| Key 示例 | 类型 | TTL | 写入者/读取者 | 失效与回源 |
|---|---|---|---|---|
| `auth:principal:2d…` | Hash：`role/status/securityVersion` | 15 分钟 | 每次 JWT 校验写；运维观察 | 权限变化删除；授权仍读 MySQL，Redis 失败不放宽权限 |
| `auth:refresh:user:2d…` | Set：该用户 tokenId | 跟随成员令牌，集合续到最长刷新 TTL | 签发/旋转写；管理员撤权批量读取 | 撤权删除每个 `auth:refresh:{tokenId}` 和集合 |
| `community:post:8a…` | String(JSON) | 10 分钟 | 公开详情读写 | 编辑、发布、删除、计数回写后删除；未命中回源 MySQL |
| `community:post:counter:8a…` | Hash：`viewDelta` | 当前无单独 TTL，dirty Set 管理生命周期 | 详情递增；定时任务读取 | Lua 取出，成功回写 MySQL 后清理；失败恢复 |
| `community:post:counter:dirty` | Set：待回写 postId | 无固定 TTL | 详情加入；定时任务扫描 | 对应增量成功回写后移除 |
| `community:post:bloom` | Redisson Bloom Filter | 持久结构 | 启动预热/发布加入；详情判空 | Redis 丢失后从 MySQL 已发布 ID 重建 |
| `community:post:bloom:ready` | String `1` | 无固定 TTL | 全量预热完成后写；详情读取 | 不存在时跳过 Bloom 并回源，防止假阴性 |

缓存只保存查询副本和可恢复增量，帖子、用户权限、审计和 Outbox 的最终状态全部在 MySQL。

## 7. 接口公共约定

- 除 `GET /api/v1/system/health` 外，本章接口都需要 `Authorization: Bearer <accessToken>`。
- 管理接口与知识测试只接受 `ADMIN`；社区接口只接受 `USER/VERIFIED_SELLER`。
- JSON 时间均为 ISO-8601，例如 `2026-08-22T05:20:30.123Z`。
- 统一错误体：`{ "code": string, "message": string, "timestamp": string }`。
- 公共错误：无令牌/无效令牌 `401 AUTHENTICATION_REQUIRED`；角色不允许 `403 ACCESS_DENIED`；数据库故障 `503 DATABASE_UNAVAILABLE`；JSON 错误 `400 INVALID_JSON`；字段或业务校验失败 `400 INVALID_REQUEST`。

- Body：`title/content/petProfileId/topicId/region/mediaIds` 与 9.2 相同但都可选；`version:int` 必填，应传当前响应中的版本。若字段为 `null` 表示保持原值；`mediaIds:[]` 表示清空媒体。
- 响应 `200 CommunityPostResponse`，成功后 `version + 1`。
- 特有错误：帖子不存在或不属于自己 `404 COMMUNITY_POST_NOT_FOUND`；版本过期 `409 COMMUNITY_POST_CONFLICT`。

### 9.4 发布帖子

`POST /api/v1/community/posts/{postId}/publish`

- Path `postId:string` 必填；Query/Body 无。
- 响应 `200 CommunityPostResponse`，`status=PUBLISHED`、`publishedAt` 非空。
- 同事务创建 `POST_PUBLISHED` Outbox。帖子不存在/非本人返回 404。

### 9.5 删除帖子

`DELETE /api/v1/community/posts/{postId}`

- Path `postId:string` 必填；Query/Body 无。
- 响应 `204` 无 Body。执行逻辑删除、解绑媒体、删除详情缓存；已签发的 1 分钟 MinIO 下载 URL 可能在自身到期前仍有效，这是预签名 URL 的时间窗口，后续可通过网关代理实现实时吊销。
- 不存在/非本人返回 `404 COMMUNITY_POST_NOT_FOUND`。

### 9.6 公开帖子详情

`GET /api/v1/community/posts/{postId}`

- Path `postId:string` 必填；Query/Body 无。
- 响应 `200 CommunityPostResponse`，只返回 `PUBLISHED` 状态；浏览数包含 MySQL 基数加当前 Redis 待回写增量。
- 不存在或非公开返回 `404 COMMUNITY_POST_NOT_FOUND`。

### 9.7 公开帖子分页

`GET /api/v1/community/posts`

| Query | 类型 | 必填 | 默认/限制 |
|---|---|---:|---|
| `topicId` | string | 否 | 空，按话题过滤 |
| `authorId` | string | 否 | 空，按作者主页过滤 |
| `page` | int | 否 | 0，零基 |
| `size` | int | 否 | 20，服务端限制 1～50 |

响应 `200 CommunityPostPageResponse`：`items:CommunityPostResponse[]`、`page`、`size`、`total`。

### 9.8 我的帖子

`GET /api/v1/community/posts/mine`

- Query：`page:int=0`，`size:int=20`（1～50）；Path/Body 无。
- 响应 `200 CommunityPostPageResponse`，包含当前用户草稿、已发布等未删除帖子，便于继续编辑。

## 10. 媒体接口参数字典

### 10.1 申请上传地址

`POST /api/v1/community/media/upload-url`

Body：`fileName:string` 必填、≤255；`contentType:string` 必填；`sizeBytes:long` 必填、1～52428800；`checksumSha256:string` 可选，空或 64 位十六进制。Path/Query 无。

允许 Content-Type：`image/jpeg,image/png,image/webp,video/mp4,video/webm`。图片业务上限 10 MiB，视频 50 MiB。

响应 `201 MediaUploadResponse`：`mediaId:string`、`objectKey:string`、`uploadUrl:string`、`httpMethod:"PUT"`、`expiresAt:string`。随后浏览器必须用相同 Content-Type 对 `uploadUrl` 执行 PUT。

特有错误：格式或大小不允许 `400 INVALID_REQUEST`；MinIO 未启动 `503 MEDIA_STORAGE_UNAVAILABLE`。

### 10.2 确认上传

`POST /api/v1/community/media/{mediaId}/confirm`

- Path `mediaId:string` 必填；Query/Body 无。
- 响应 `200 CommunityMediaResponse`：`id,mediaType,contentType,originalFilename,sizeBytes,status,processingStatus,confirmedAt`。
- 重复确认同一个已确认媒体是幂等操作，返回当前记录；非本人/记录不存在 `404 COMMUNITY_MEDIA_NOT_FOUND`；对象不存在或 MinIO 故障 `503 MEDIA_STORAGE_UNAVAILABLE`；实际大小/类型不符 `400 INVALID_REQUEST`。

### 10.3 获取短期下载地址

`GET /api/v1/community/media/{mediaId}/download-url`

- Path `mediaId:string` 必填；Query/Body 无。
- 只有媒体所有者，或媒体已经绑定到公开帖子时允许访问。
- 响应 `200`：`url:string`、`expiresAt:string`，默认 1 分钟。
- 不满足归属/公开条件统一返回 `404 COMMUNITY_MEDIA_NOT_FOUND`，不泄露对象是否存在。

### 10.4 帖子中的媒体摘要

帖子响应的 `media[]` 不包含永久公网 URL和 `objectKey`，只有：`id,mediaType,contentType,originalFilename,sizeBytes,status,processingStatus,confirmedAt`。显示文件时前端再调用 10.3 取得短期 URL。

## 11. 健康接口参数字典

`GET /api/v1/system/health`，公开接口，无 Path/Query/Body。

响应 `200`：

{
  "businessService": "UP",
  "aiService": "UP|DOWN",

## 15. 故障排查

- 页面提示媒体服务不可用：访问系统状态确认 `minio=DOWN`，检查 9000 端口和 `.env` 凭据。
- 媒体确认提示大小不一致：申请 URL 时的 `sizeBytes` 必须等于上传对象实际大小，重新申请并上传。
- RabbitMQ 停止后帖子仍发布：这是 Outbox 设计的正常行为；查看 `integration_outbox`，恢复 RabbitMQ 后等待发布器重试。
- 帖子更新 409：页面的 `version` 已过期，重新加载帖子再编辑，不能覆盖新版本。
- 管理员突然 401：角色/状态刚被其他管理员修改，旧 JWT 的安全版本已经失效，需用仍有效的账号重新登录。
- 管理员看不到普通问答：这是本周要求的角色隔离，不是页面故障。管理员用知识页的 RAG 测试验证 AI/知识能力。
