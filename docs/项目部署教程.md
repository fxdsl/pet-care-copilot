# 宠里个宠项目部署教程（自己动手版）

> 适用版本：第十四周简化架构，2026-08-28
> 目标读者：第一次完整部署 Vue + Spring Boot + FastAPI + 多中间件项目的开发者
> 原则：本文告诉你每一步做什么、为什么做、如何验证和如何回滚。Codex 不替你执行部署。

## 1. 先理解“部署”在做什么

开发时你分别运行前端、Java、Python 和各中间件；部署只是把这些程序变为可重复构建、按依赖顺序启动、可持久保存数据、可观察并可恢复的一组服务。

```text
用户浏览器
  ↓ HTTP（正式环境应为 HTTPS）
Nginx :80
  ├─ /assets → Vue 构建产物
  ├─ /api    → Business :8080
  └─ /ws     → Business WebSocket

Business
  ├─ MySQL：最终业务数据
  ├─ Redis：缓存、限流、在线状态和加速结构
  ├─ RabbitMQ：异步事件
  ├─ MinIO：图片、视频、PDF
  ├─ OpenSearch：可重建搜索副本
  └─ FastAPI：Agent、Embedding、PDF 处理

Prometheus → 抓取 Business 指标 → Grafana 展示
```

这是当前推荐的模块化单体结构：Java 业务仍按 controller、service、data、mapper 等包分层，但只部署一个 Business 应用，不要求 Spring Cloud。仓库保留 `backend/gateway-service`，且 Compose 将它放在 `microservices` profile 中；它用于以后真正拆成多个服务时复用，默认部署不会启动，也不在当前请求链中。

不要把“容器启动了”当成部署成功。成功至少包括：健康检查、数据库迁移、管理员登录、图片上传、问答、搜索、消息队列、监控、备份和回滚演练。

## 2. 准备条件

### 2.1 Windows 学习环境

建议：Windows 11 64 位、16 GB 内存（OpenSearch 较吃内存）、至少 25 GB 可用空间。

1. 在“启用或关闭 Windows 功能”启用“适用于 Linux 的 Windows 子系统”和“虚拟机平台”。
2. 以管理员 PowerShell 执行：

```powershell
wsl --install
wsl --update
```

3. 重启 Windows。
4. 从 [Docker Desktop 官方页面](https://docs.docker.com/desktop/setup/install/windows-install/)安装 Docker Desktop，选择 WSL 2 后端。
5. Docker Desktop → Settings → Resources，建议先分配 8 GB 内存、4 CPU；机器内存不足时可降低 OpenSearch 堆，但不建议低于 512 MB。
6. 安装 Git；项目的 Java、Node、Python 在镜像内部构建，本机不必为了部署重复安装。

验证：

```powershell
docker version
docker compose version
git --version
```

三个命令都应返回版本，不应出现“不是内部或外部命令”。如果 Docker 显示无法连接 daemon，先启动 Docker Desktop，等左下角变为 Engine running。

### 2.2 Linux 服务器（以后正式部署）

正式服务器建议 Ubuntu LTS，安装 Docker Engine 和 Compose 插件，参考 [Docker Engine 官方安装文档](https://docs.docker.com/engine/install/)。不要复制来源不明的一键安装脚本。云安全组只开放 22、80、443；数据库和管理端口只允许内网/VPN。

本教程先以 Windows 本机为例。掌握后迁移 Linux，Compose 文件和命令基本相同。

## 3. 获取代码并确认版本

第一次部署：

```powershell
Set-Location G:\develop
git clone https://github.com/fxdsl/pet-care-copilot.git
Set-Location .\pet-care-copilot
git status
git log -1 --oneline
```

如果已经克隆：

```powershell
Set-Location G:\develop\pet-care-copilot
git status
git pull --ff-only
```

`git status` 有自己未提交的文件时不要直接覆盖。先提交、暂存或复制备份，再更新。部署应记录具体 commit，例如：

```powershell
git rev-parse HEAD
```

故障时你才能准确回到旧版本，而不是猜“昨天那版”。

## 4. 创建部署环境变量

复制模板：

```powershell
Copy-Item .\deploy\.env.deploy.example .\deploy\.env.deploy
notepad .\deploy\.env.deploy
```

`.env.deploy` 已被 Git 忽略，绝不能提交。必须修改所有 `replace_with_...`：

| 变量 | 含义 | 要求 |
|---|---|---|
| `MYSQL_PASSWORD` | 应用数据库用户密码 | 随机、与 root 不同 |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | 只用于维护，不给应用 |
| `REDIS_PASSWORD` | Redis 密码 | 随机长密码 |
| `RABBITMQ_PASSWORD` | RabbitMQ 应用密码 | 随机长密码 |
| `MINIO_SECRET_KEY` | 对象存储密钥 | 至少 16 字符，建议 32+ |
| `JWT_SECRET` | JWT HMAC 密钥 | 至少 32 个随机字符，生产建议 64 字节 |
| `BOOTSTRAP_ADMIN_*` | 首次管理员 | 只在首次启动暂时保留 |
| `DASHSCOPE_API_KEY` | 阿里云百炼 Key | 可留空，此时需要通用模型的功能会明确失败；本地 Embedding 不收费 |
| `GRAFANA_ADMIN_PASSWORD` | Grafana 管理密码 | 与其他服务不同 |

PowerShell 生成随机 JWT 示例：

```powershell
$bytes = New-Object byte[] 48
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

只复制输出到 `.env.deploy`，不要把真实密钥粘贴到聊天、截图、README 或 GitHub Issue。

免费额度说明：`AI_LLM_CHAT_MODEL=qwen3.7-plus` 只是模型名称，是否免费由百炼账号活动、地域和实时计费规则决定；部署前应在百炼控制台设置预算/额度告警。完全不调用付费模型可让 `DASHSCOPE_API_KEY` 为空，但智能问答和 AI 预检不会完整工作，本地 BGE 搜索向量仍可运行。

## 5. 配置 MinIO 可解析域名

项目使用 `pet-files.local`：

- Business 容器通过 Docker 网络别名找到 MinIO。
- 浏览器通过 Windows hosts 把同一主机名指向 `127.0.0.1`。
- 预签名 URL 的签名 Host 保持一致，避免“上传成功但图片不显示”。

以管理员身份打开记事本，再打开：

```text
C:\Windows\System32\drivers\etc\hosts
```

增加：

```text
127.0.0.1 pet-files.local
```

保存后验证：

```powershell
Resolve-DnsName pet-files.local
```

应解析到 `127.0.0.1`。正式服务器不能继续使用 `.local`；应准备真实域名，例如 `files.example.com`，让容器和用户浏览器都能解析，并配置 HTTPS。更换 MinIO Endpoint 后旧预签名 URL 自然过期，数据库只保存 object key，不需要改历史对象路径。

## 6. 先做静态配置检查

这一步只解析 Compose，不启动服务：

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml config --quiet
```

无输出且退出码为 0 表示 YAML 和变量替换正常。若提示变量缺失，回到 `.env.deploy`；若提示找不到文件，确认当前目录是仓库根目录。

查看将要启动的服务：

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml config --services
```

默认应包含 `mysql redis rabbitmq minio opensearch ai-service business-service frontend prometheus grafana`，共 10 个活动服务。Gateway 是第 11 个服务定义，但因为带 `microservices` profile，默认不会出现在活动服务列表。

如需确认预留定义仍然有效，可以只做配置解析，不启动：

```powershell
docker compose --profile microservices --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml config --services
```

此时列表才会额外出现 `gateway`。

## 7. 第一次构建镜像

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml build
```

默认会看到四类构建步骤：

1. Maven 下载依赖并打包 Business JAR。
2. pip 安装 FastAPI 依赖。
3. npm 执行 `npm ci`、类型检查和 Vite 生产构建。
4. Nginx 镜像接收 `dist` 静态文件。

Gateway 默认不构建。以后学习微服务拆分时，可以显式执行 `docker compose --profile microservices ... build gateway` 验证保留模块，但这不会自动把前端切换到 Gateway。

第一次可能较慢。不要因几分钟没有新行就结束 Docker；若失败，先看最靠近末尾的第一个错误：

- Maven 依赖下载失败：检查网络/DNS，重试 build。
- `npm ci` lockfile 错误：开发阶段先修复 `package-lock.json`，不要在服务器临时 `npm install`。
- Python 包编译失败：记录具体包和架构。
- 磁盘不足：Docker Desktop 清理无用构建缓存，但不要删除项目数据卷。

## 8. 分阶段启动，学会定位问题

不要第一次就只盯着一个长日志。按依赖分层更容易学习。

### 8.1 数据与中间件

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml up -d `
  mysql redis rabbitmq minio opensearch

docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml ps
```

等所有服务显示 `healthy`。查看某个服务：

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml logs --tail 100 mysql
```

将最后的 `mysql` 换成 `redis/rabbitmq/minio/opensearch` 分别检查。

### 8.2 FastAPI

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml up -d ai-service

docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml logs -f ai-service
```

首次生成向量时 FastEmbed 可能下载模型，模型缓存保存到命名卷。按 `Ctrl+C` 只退出日志跟随，不会停止容器。

### 8.3 Business 与 Flyway

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml up -d business-service

docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml logs --tail 200 business-service
```

启动时 Flyway 自动执行 V1～V11。日志不应出现 `Validate failed` 或 `checksum mismatch`。绝不能为了通过校验去修改已执行的 V1～V11；新结构必须创建 V12。

验证：

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml exec mysql `
  mysql -u root -p -e "USE pet_assistant; SELECT version,description,success FROM flyway_schema_history ORDER BY installed_rank;"
```

命令会让你输入 root 密码。最新版本应为 11 且 `success=1`。

### 8.4 前端和监控

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml up -d frontend prometheus grafana

docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml ps
```

最终所有服务应是 running/healthy。浏览器打开：

- 项目：`http://localhost`
- RabbitMQ：`http://localhost:15672`
- MinIO Console：`http://localhost:9001`
- Prometheus：`http://localhost:9090`
- Grafana：`http://localhost:3000`

管理页面只绑定本机。不要通过路由器端口映射把它们直接暴露公网。

## 9. 首次管理员与安全收尾

`.env.deploy` 的 `BOOTSTRAP_ADMIN_USERNAME/PASSWORD` 只在用户名不存在时创建管理员。用该账号登录成功后：

1. 在管理端新建或提升长期管理员账号。
2. 清空 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD`。
3. 重新创建 Business 容器以清除容器环境中的初始密码：

```powershell
docker compose --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml up -d --force-recreate business-service
```

不要把普通用户注册页变成管理员注册入口。管理员必须由已有管理员在受保护流程中创建/授权并写审计日志。

## 10. 功能验收清单

按顺序操作并记录时间、结果、截图：

- [ ] 注册普通用户，登录后刷新页面仍保持登录。
- [ ] 同一浏览器两个标签页是同一账号属于正常；要同时测试两个账号，用普通窗口 + 无痕窗口或两个浏览器，避免共享 localStorage。
- [ ] 创建宠物档案、发布带图片帖子，图片能预览且没有 `R.jpg` 文件名按钮。
- [ ] 点赞、评论、关注、转发、不感兴趣、屏蔽和拉黑符合权限。
- [ ] 私信和通知离线后从 MySQL 恢复。
- [ ] 智能问答能返回会话 ID、模型标记和真实来源。
- [ ] 管理员上传 PDF，RabbitMQ 完成预检和知识发布。
- [ ] 搜索命中公开帖子/知识；关闭 OpenSearch 后页面明确显示 MySQL 安全降级。
- [ ] Prometheus `Status → Targets` 的 Business 是 UP，默认不应出现 Gateway 的 DOWN 目标。
- [ ] Grafana Dashboard 有 HTTP、JVM、Outbox、Agent 和队列数据。
- [ ] RabbitMQ 队列没有持续增长的积压。
- [ ] 未登录访问管理接口为 401，普通用户访问为 403。

### 10.1 验证限流

不要对生产账号做压力测试。本机可连续请求一个公开的登录前业务入口并观察 `429`。默认 Nginx 在 `frontend/nginx.conf` 中配置每个来源 IP 每秒 20 次、突发 40 次的基础限制；登录、验证码、问答等精确限制由 Spring Boot + Redis 完成。

为便于学习，可在本地分支临时降低 Nginx 的 `rate` 和 `burst`，重新构建 `frontend` 后测试，再恢复。不要把压测脚本指向第三方或线上生产。

### 10.2 Lighthouse 和响应式截图

部署后用 Chrome DevTools → Lighthouse，分别测试登录页、社区、问答和搜索。登录态页面可在已登录标签中运行。记录 Performance、Accessibility、Best Practices，不要只保留最好的一次。

DevTools 设备工具栏依次输入 360、768、1280、1600 宽度，检查：

- 无页面级横向滚动；固定布局的功能区独立滚动。
- 键盘能访问按钮、表单和弹窗。
- 图片有占位、失败状态和预览。
- 列表的加载、空、错误、重试状态都能看见。

实际分数和截图应回填 `docs/第十四周.md`。没有执行就不能写“已达到 90”。

## 11. 日常查看与停止

查看状态：

```powershell
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml ps
```

跟随全部日志：

```powershell
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml logs -f --tail 100
```

正常停止并保留数据：

```powershell
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml down
```

再次启动：

```powershell
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml up -d
```

不要执行 `docker compose down -v`。`-v` 会删除 MySQL、Redis、RabbitMQ、MinIO、OpenSearch、Grafana 和模型缓存卷，属于数据清空操作。

## 12. 更新部署

每次更新先记录和备份：

```powershell
git rev-parse HEAD
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml ps
```

然后：

```powershell
git pull --ff-only
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml build
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml up -d
```

Compose 只重建发生变化的容器，命名卷保留。Business 启动前 Flyway 会迁移；有新迁移时必须先备份 MySQL。

## 13. 备份与恢复演练

### 13.1 MySQL

创建本机备份目录：

```powershell
New-Item -ItemType Directory -Force .\backups
```

为避免命令行泄露密码，进入容器交互执行：

```powershell
docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml exec mysql bash
mysqldump -u root -p --single-transaction --routines --triggers pet_assistant > /tmp/pet_assistant.sql
exit
```

复制到主机：

```powershell
$mysqlContainer = docker compose --env-file .\deploy\.env.deploy -f .\deploy\docker-compose.full.yml ps -q mysql
docker cp "${mysqlContainer}:/tmp/pet_assistant.sql" ".\backups\pet_assistant.sql"
```

恢复不能只看命令成功，必须在隔离的测试数据库导入并验证表数、Flyway 版本和核心行数。不要第一次在事故当天学习恢复。

### 13.2 MinIO

数据库备份不包含图片/PDF。使用 MinIO Client `mc mirror` 把桶同步到独立磁盘或备份对象存储。备份时同时记录 `community_media.object_key` 与桶名。

### 13.3 Redis、RabbitMQ、OpenSearch

- Redis AOF 和 RabbitMQ 卷用于运行恢复，但不能代替 MySQL/MinIO 备份。
- OpenSearch 是查询副本，可以从 MySQL 全量重建；不要把它当唯一备份。
- Prometheus/Grafana 数据可按监控保留策略备份，Dashboard 配置已经在 Git 中。

## 14. 回滚策略

应用出问题但迁移向后兼容时：

1. 记录错误日志和当前 commit。
2. 切回已验证 commit 或 tag。
3. 重新 build 并 `up -d`。
4. 保留新增数据库列/表，让旧应用忽略它们。

不要自动执行 Flyway 向下删除表。若新版本已经写入新格式数据，先评估数据兼容，再决定数据修复。MySQL 故障则从验证过的备份恢复到新实例，核对后切换，不在原数据上反复试错。

## 15. 常见故障定位

### 15.1 80/8080 被占用

默认 Compose 只把 Nginx 的 `80` 暴露给浏览器，Business `8080` 只在容器网络使用。若主机的 `80` 被占用，先查清进程；若是本地开发模式的 Spring Boot 报 `8080` 被占用，则检查 `8080`：

```powershell
Get-NetTCPConnection -LocalPort 80 -State Listen | Select-Object OwningProcess
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object OwningProcess
Get-Process -Id <PID>
```

Gateway 的 `8088` 默认不启动。先确认进程身份，再决定关闭；不要看到 PID 就盲目结束系统服务。

### 15.2 图片灰块或不显示

依次检查：

1. `Resolve-DnsName pet-files.local` 是否为 127.0.0.1。
2. 浏览器 Network 中图片 URL 是否为 `http://pet-files.local:9000/...`。
3. MinIO 是否 healthy，9000 是否监听。
4. URL 是否过期；下载预签名 URL 默认一分钟，需要刷新帖子数据。
5. `.env.deploy` 的 `MINIO_ENDPOINT` 与请求 Host 是否一致。

### 15.3 搜索没有结果

1. 看页面是否显示 MySQL 降级。
2. 管理端检查 OpenSearch health。
3. 查看 `search_index_job` 的 total/indexed/failed。
4. 查看 Business 和 OpenSearch 日志中的第一个 mapping 错误。
5. 修复后从 MySQL 全量重建，不手工往 OpenSearch 塞业务数据。

### 15.4 AI 服务显示开着但业务说不可用

容器“running”不代表端到端可用。检查：

- `ai-service` health 是否 UP。
- Business 使用的 `AI_SERVICE_BASE_URL=http://ai-service:8000`，不能在容器里写 localhost。
- `DASHSCOPE_API_KEY` 是否进入容器、模型名是否可用、免费额度是否结束。
- Business 的 Resilience4j circuitbreaker 是否 OPEN；等待 30 秒进入 half-open 后再试。
- FastAPI/Business 日志中的同一个 `requestId`。

### 15.5 所有索引重建都失败

查看第一个失败原因，不要反复点按钮。常见原因是向量维度不一致、旧 Mapping、OpenSearch 地址错误。确认 `AI_EMBEDDING_DIMENSIONS=512`，删除并重建查询副本只能通过管理接口，MySQL 业务数据不应被删除。

## 16. 后期拆分微服务时如何复用 Gateway

当前不要为了“用了 Spring Cloud”而把单体强行拆开。只有出现某个模块需要独立扩容、独立发布、独立数据库边界或独立团队维护时，才进入拆分设计。

保留模块可以先单独验证：

```powershell
docker compose --profile microservices --env-file .\deploy\.env.deploy `
  -f .\deploy\docker-compose.full.yml up -d gateway
```

这条命令只会启动 Gateway 储备容器，**不会**自动让当前前端改走 Gateway。真正拆分时还要完成以下工作：

1. 明确要拆出的业务边界、独立数据所有权和跨服务一致性方案。
2. 为新服务建立独立健康检查、鉴权边界、超时、监控与部署配置。
3. 在 Gateway 中增加明确路由，不能继续把全部路径无差别转给一个单体。
4. 将 `frontend/nginx.conf` 的 `/api`、`/ws` 上游切换为 `gateway:8088`，并把 `frontend.depends_on` 改为 Gateway。
5. 为 Prometheus 增加 Gateway 与新服务抓取目标，再做权限、限流、WebSocket/SSE 和故障演练。

因此，现有 Gateway 是“可复用起点”，不是已经完成的微服务架构。

## 17. 正式上线前必须追加的生产措施

当前 Compose 适合本机学习和单机演示。对公网正式上线前还必须：

- 使用真实域名和 HTTPS 证书，HTTP 自动跳转 HTTPS。
- 密钥进入 Docker Secret/云 Secret Manager，不只放 `.env`。
- 数据库、Redis、RabbitMQ、MinIO、OpenSearch 使用独立账号和最小权限。
- 管理端口只允许内网/VPN，配置主机防火墙和云安全组。
- MySQL/MinIO 自动异地备份并定期恢复演练。
- 配置 Prometheus 告警：高 5xx、P95 延迟、队列积压、磁盘、熔断开启、备份失败。
- 设置日志轮转和保留周期，确认日志不含 Token、Key、手机号、正文。
- 做依赖漏洞扫描、镜像固定版本、权限测试、限流测试和灾难恢复演练。
- 准备蓝绿或滚动发布；当前单机 Compose 更新会有短暂停机。

完成这些以后，才可以把“本机演示部署”提升为“可对公网负责的生产部署”。
