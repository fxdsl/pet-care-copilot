# 第十三周：个性化推荐、社区治理与可审计定时任务

> 完成日期：2026-08-27
> 数据库：Flyway V11
> 核心技术：Spring Boot、MyBatis XML、Redis Set/ZSet/Hash/Stream、RabbitMQ Outbox、Quartz、Redisson、Vue 3
> 设计边界：MySQL 保存业务事实；推荐只改变排序，不改变知识可信等级，也不会把社区帖子自动写入 RAG。

## 1. 本周交付结果

```text
转发/屏蔽/拉黑/不感兴趣
  → Controller 校验身份和参数
  → Service 在一个事务中修改 MySQL + 写 integration_outbox
  → 同步 Redis 加速副本并失效推荐结果
  → Outbox 定时发布 RabbitMQ
  → 消费者按 eventId + consumerName 幂等认领

推荐请求
  → MySQL 读取公开候选
  → 排除本人、拉黑/屏蔽作者和不感兴趣帖子
  → 关注关系、宠物类型、话题、互动质量、时间衰减打分
  → 返回主要推荐原因
  → ZSet/Hash 保存可重建的短期排序副本

Quartz 维护
  → 每个实例都触发
  → Redisson Lock 只允许一个实例执行同一任务
  → scheduled_job_execution 留下结果和失败原因
  → 三次失败后进入人工处理，不无限重试
```

完成的用户能力：

- 普通转发与带 500 字以内说明的引用转发；重复请求不会增加计数。
- 取消转发；计数始终由关系表重新聚合，不信任前端数字。
- 屏蔽 `MUTE`、拉黑 `BLOCK` 及撤销；拉黑会解除双方关注。
- 拉黑同时约束信息流、推荐、评论可见性和私信权限。
- “为你推荐”信息流展示主要推荐原因。
- “不感兴趣”与撤销反馈，反馈只过滤当前用户结果。
- 趋势快照、知识过期、Outbox 补偿、旧审计归档和队列积压五类 Quartz 任务。
- RabbitMQ 消费事件认领表和 Outbox 人工处理表。

| 表/字段 | 最终事实 | 关键约束 |

## 4. 核心代码讲解

### 4.1 幂等转发

```java
CommunityRepostEntity existing = mapper.findRepost(postId, userId);
CommunityRepostEntity saved = new CommunityRepostEntity(
        existing == null ? UUID.randomUUID().toString() : existing.id(),
        postId, userId, quoteContent, active,
        existing == null ? now : existing.createdAt(), now
);
mapper.upsertRepost(saved);
mapper.synchronizeRepostCount(postId);
```

第一次请求创建关系，后续 PUT/DELETE 只改变同一行的 `active`。唯一索引阻止并发产生两行；计数使用 SQL 对有效关系重新 `COUNT`，不会因网络重试膨胀。

### 4.2 拉黑不是一个前端标签

```java
if (active && "BLOCK".equals(type)) {
    socialMapper.deleteFollow(userId, targetUserId);
    socialMapper.deleteFollow(targetUserId, userId);
    socialCache.synchronizeFollow(userId, targetUserId, false);
    socialCache.synchronizeFollow(targetUserId, userId, false);
}
```

MySQL 关系先落库，再解除双方关注并更新缓存。信息流、评论和私信 Service 也调用双向拉黑检查，因此隐藏按钮不会成为唯一安全措施。

### 4.3 可解释推荐打分

```java
double score = (like * 3 + comment * 4 + favorite * 5
        + repost * 6 + Math.log1p(view)) / Math.pow(ageHours + 2, 1.1);
if (followed.contains(authorId)) {
    score += 80;
    reason = "来自你关注的宠友";
} else if (petTypes.contains(postPetType)) {
    score += 45;
    reason = "与你的宠物类型相关";
} else if (preferredTopics.contains(topicId)) {
    score += 30;
    reason = "符合你常看的话题";
}
```

互动信号经过时间衰减，关注、宠物类型和话题只提供可解释加权。调用前先排除本人、治理关系和不感兴趣内容。该分数不参与 RAG 信任等级。

### 4.4 Redis 推荐副本

```java
redisTemplate.opsForZSet().add(rankingKey, item.postId(), item.score());
redisTemplate.opsForHash().put(explanationKey, item.postId(), item.reason());
redisTemplate.expire(rankingKey, Duration.ofMinutes(30));
redisTemplate.expire(explanationKey, Duration.ofMinutes(30));
```

ZSet 用于排序，Hash 保存同批解释。关系或反馈变化时同时删除两个 Key；Redis 故障只跳过缓存写入，当前请求仍以 MySQL 事实计算。

### 4.5 反馈 Stream

```java
redisTemplate.opsForStream().add(StreamRecords.newRecord()
        .in("recommendation:feedback:stream")
        .ofMap(Map.of("feedbackId", id, "userId", userId,
                "postId", postId, "active", Boolean.toString(active))));
redisTemplate.opsForStream().trim("recommendation:feedback:stream", 10_000, true);
```

Set 用于在线过滤，Stream 为后续离线排序提供有界重放记录。Stream 不是授权或反馈的最终事实；丢失后从 `community_recommendation_feedback` 重建。

### 4.6 Quartz 单实例执行与人工处理

```java
RLock lock = redissonClient.getLock("scheduler:lock:" + task.toLowerCase());
if (!lock.tryLock(0, 10, TimeUnit.MINUTES)) return;
try {
    executeWithAudit(task);
} finally {
    if (lock.isHeldByCurrentThread()) lock.unlock();
}
```

锁减少多实例重复，但正确性仍由 MySQL 状态条件和唯一键保证。每批最多尝试三次，最终状态写 `MANUAL_REVIEW`，错误原因保留，避免静默丢任务或无限循环。

## 5. 新增接口完整契约

所有接口都经 Gateway，必须携带 `Authorization: Bearer <accessToken>`；允许角色为 `USER`、`VERIFIED_SELLER`。成功响应是 JSON，时间使用 ISO-8601。

### 5.1 转发或引用转发

`PUT /api/v1/community/posts/{postId}/repost`

| 位置 | 参数 | 类型 | 必填 | 规则 |
|---|---|---|---|---|
| Path | `postId` | string(UUID) | 是 | 已公开帖子 ID |
| Body | `quoteContent` | string/null | 否 | 去首尾空格，最多 500 字；空表示普通转发 |

请求：

```json
{ "quoteContent": "这篇幼猫喂养经验很实用" }
```

响应 `200`：`{"active":true,"count":3}`。`active` 是当前用户状态，`count` 是帖子有效转发总数。

错误：`400` 参数超长、自己/目标关系不允许；`401` 未登录；`404` 帖子不存在或不可公开查看。

### 5.2 取消转发

`DELETE /api/v1/community/posts/{postId}/repost`

Path 只有 `postId`，无 Query、无 Body。响应 `200`：`{"active":false,"count":2}`。重复 DELETE 仍返回当前状态。

### 5.3 屏蔽或拉黑用户

`PUT /api/v1/community/users/{userId}/{relationType}`

| 位置 | 参数 | 类型 | 必填 | 规则 |
|---|---|---|---|---|
| Path | `userId` | string(UUID) | 是 | 目标用户，不能是自己 |
| Path | `relationType` | string | 是 | `MUTE` 或 `BLOCK`，大小写不敏感 |

无 Query、无 Body。响应 `200`：

```json
{ "userId":"target-uuid", "relationType":"BLOCK", "active":true }
```

`MUTE` 只影响发起者看到的内容；`BLOCK` 双向限制内容和私信并解除双方关注。错误：`400` 类型错误/操作自己/目标不可用，`401` 未登录。

### 5.4 撤销屏蔽或拉黑

`DELETE /api/v1/community/users/{userId}/{relationType}`

Path 规则同 5.3，无 Query、无 Body。响应 `active=false`。撤销拉黑不会自动恢复以前的关注关系。

### 5.5 获取个性化推荐

`GET /api/v1/community/recommendations`

| 位置 | 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|---|
| Query | `page` | integer | 否 | 默认 0，负数归一为 0 |
| Query | `size` | integer | 否 | 默认 20，范围 1～50 |

响应 `200`：

```json
{
  "items": [{
    "post": { "id":"post-uuid", "title":"幼猫如何养", "repostCount":2 },
    "score": 83.42,
    "reason": "来自你关注的宠友",
    "viewerNotInterested": false
  }],
  "page": 0,
  "size": 20,
  "total": 1
}
```

`post` 的完整字段与第九周 `CommunityPostResponse` 一致。空结果返回 `items=[]/total=0`，不是 404。

### 5.6 标记不感兴趣

`PUT /api/v1/community/recommendations/{postId}/not-interested`

Path 为公开 `postId`，无 Query、无 Body。响应 `200`：`{"postId":"post-uuid","active":true}`。错误：`404` 帖子不存在。

### 5.7 撤销不感兴趣

`DELETE /api/v1/community/recommendations/{postId}/not-interested`

参数同 5.6。响应 `active=false`；下一次推荐是否立即出现仍取决于排序和分页。

通用错误体：

```json
{ "status":400, "code":"VALIDATION_FAILED", "message":"...", "timestamp":"..." }
```

## 6. Redis 数据字典

| Key | 类型 | 示例内容 | TTL | 写入/读取 | 失效、回源与故障行为 |
|---|---|---|---|---|---|
| `community:user:{uid}:muted` | Set | `targetUserId` | 30 天 | 关系 Service 写；信息流过滤 | 撤销移除；MySQL `community_user_relation_control` 回源 |
| `community:user:{uid}:blocked` | Set | `targetUserId` | 30 天 | 关系 Service 写；快速过滤 | 双向安全判断最终查 MySQL；Redis 故障不能放宽私信权限 |
| `community:user:{uid}:reposts` | Set | `postId` | 30 天 | 转发 Service 写 | `community_post_repost` 重建；失败不影响转发事实 |
| `recommendation:user:{uid}:not-interested` | Set | `postId` | 30 天 | 反馈 Service 写；候选过滤 | 撤销移除；MySQL 回源 |
| `recommendation:user:{uid}:candidates` | ZSet | `postId → score` | 30 分钟 | 推荐 Service 写 | 关系/反馈变化删除；重新请求从 MySQL 重建 |
| `recommendation:user:{uid}:explanations` | Hash | `postId → reason` | 30 分钟 | 与候选同批写 | 与 ZSet 同时删除，不能单独长期保存 |
| `recommendation:feedback:stream` | Stream | feedbackId/userId/postId/active/time | 近似保留 10,000 条 | 反馈 Service 写；离线排序器可消费 | MySQL 是事实，可重新发布 |
| `scheduler:lock:{task}` | Redisson Lock | 锁所有者 | 最长 10 分钟租约 | Quartz 竞争 | 只防重复执行，不替代数据库幂等 |
| `platform:queue:backlog` | Hash | queue → count | 10 分钟 | Quartz 被动声明队列后写；监控读 | 下一次采样重建，丢失不影响消息 |

## 7. RabbitMQ、Outbox 与定时任务

- Service 在业务事务中写 `integration_outbox`；先提交事实，再异步发布。
- 发布消息包含稳定 `eventId`；`processed_integration_event` 让每个消费者只认领一次。
- RabbitMQ 短时不可用时 Outbox 保持 `FAILED` 和重试时间。
- 达到上限后写 `integration_event_manual_review`，原事件不删除。
- `TREND_SNAPSHOT` 保存前 50 个趋势结果。
- `KNOWLEDGE_EXPIRY` 使过期知识退出检索。
- `OUTBOX_RECOVERY` 恢复卡住的索引事件并生成待人工处理项。
- `AUDIT_ARCHIVE` 在同一事务中先复制 180 天前审计，再删除原表记录。
- `QUEUE_BACKLOG` 只读取队列数量并更新缓存/指标，不消费消息。

## 8. 前端路由与状态

| 页面/区域 | 路由 | 角色 | 接口 | 状态 |
|---|---|---|---|---|
| 社区推荐 | `/app/community?feed=recommended` | USER/VERIFIED_SELLER | GET recommendations | 加载、空、错误、重试、分页 |
| 帖子卡片 | 同上 | 同上 | PUT/DELETE repost | 提交中、成功、失败回滚 |
| 推荐反馈 | 同上 | 同上 | PUT/DELETE not-interested | 隐藏、撤销、错误提示 |
| 用户治理 | 用户卡片/主页 | 同上 | PUT/DELETE users relation | MUTE/BLOCK 确认、撤销 |

前端只显示后端返回的 `reason` 和真实计数，不在浏览器自行伪造推荐分或拉黑权限。

## 9. 测试与验收

- Java 完整测试：55 项通过（包含转发幂等、拉黑解除关注、推荐过滤、私信阻断和请求 ID 安全校验）。
- Vue 类型检查和生产构建通过。
- V11 由 Flyway 自动执行；部署前必须先备份并检查 `flyway_schema_history`。
- Redis 停止时缓存写入会降级，但 MySQL 事实不丢；需要在集成环境验证恢复后重建。
- RabbitMQ 重复事件由消费认领主键抵御，超过上限可人工追踪。

本周完成的是推荐治理闭环，不包含机器学习画像训练。当前算法是可读、可调试的规则排序，更适合作为教学项目的第一版。
