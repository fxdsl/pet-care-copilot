# 第十二周：统一搜索、内容发现与 OpenSearch 混合检索

> 完成日期：2026-08-26  
> 数据库：Flyway V10，26 张业务表（不含 `flyway_schema_history`）  
> 核心技术：Spring Boot、MyBatis XML、OpenSearch、RabbitMQ Outbox、Redis String/ZSet/Bloom/Lua/Redisson Lock、FastAPI 本地 BGE、Vue 3  
> 安全边界：OpenSearch 是公开查询副本，MySQL 始终是权限和内容事实源。

## 1. 本周完成结果

第十二周交付了独立统一搜索页，并把“帖子、知识、用户、话题”从 MySQL 公开事实同步为可重建的 OpenSearch 查询副本：

已完成：

## 3. 数据库 V10

迁移文件：`backend/business-service/src/main/resources/db/migration/V10__add_unified_search_history_and_rebuild_jobs.sql`。

### 3.1 `search_history`

- 每条记录只属于一个 `user_id`，查询接口始终用 `Principal.getName()` 限定。
- `query_hash = SHA-256(normalizedQuery + filtersJson)`。
- `UNIQUE(user_id, query_hash)` 让同一条件重复搜索只累计 `search_count`。
- `filters_json` 保存 type、petType、category、trustLevel、dateRange、sort；不保存访问令牌。
- 用户删除时级联删除历史；热词不从该表公开原始查询。

核心 MyBatis UPSERT：

```xml
<insert id="upsertHistory">
  INSERT INTO search_history (..., search_count, last_searched_at, ...)
  VALUES (..., 1, #{lastSearchedAt}, ...)
  ON DUPLICATE KEY UPDATE
    result_count = VALUES(result_count),
    search_count = search_count + 1,
    last_searched_at = VALUES(last_searched_at)
</insert>
```

### 3.2 `search_index_job`

状态为 `PENDING → RUNNING → COMPLETED/FAILED`。管理员 HTTP 请求只创建任务和 Outbox，不等待全部文档向量化。`total_count/indexed_count/failed_count` 供页面展示真实进度；发起管理员删除后 `requested_by` 置空，任务审计仍保留。

V10 已在本机 MySQL 8.0 实际执行，Flyway 当前版本为 10、业务表为 26 张。完整字段、主外键和索引见[数据库文档](数据库文档.md)。

## 4. 公开权限投影

全量重建、单文档增量读取和 MySQL 降级都复用相同公开条件：

```xml
SELECT ... FROM community_post p
JOIN app_user u ON u.id = p.author_id AND u.status = 'ACTIVE'
WHERE p.status = 'PUBLISHED'
UNION ALL
SELECT ... FROM knowledge_document d
WHERE d.status = 'READY' AND d.review_status = 'APPROVED'
  AND d.consent_status != 'WITHDRAWN'
  AND (d.expires_at IS NULL OR d.expires_at > CURRENT_TIMESTAMP(6))
UNION ALL
SELECT ... FROM app_user u
WHERE u.status = 'ACTIVE' AND u.role IN ('USER', 'VERIFIED_SELLER')
UNION ALL
SELECT ... FROM community_topic t WHERE t.status = 'ACTIVE'
```

这段 SQL 是降级安全的关键。OpenSearch 挂掉时不能改成对所有表做宽松 `LIKE`，否则未审核知识、草稿、隐藏帖子或被禁用用户会从降级接口泄露。

索引只保存：业务 ID、文档类型、标题、公开摘要、公开作者名/头像、来源链接、站内路由、宠物类型、分类、信任等级、发布时间和向量。它不保存密码、刷新令牌、私信、宠物私密档案、投稿原文或未审核知识。

## 5. 核心代码讲解

### 5.1 版本化结果缓存与降级

```java
long version = cacheService.indexVersion();
String cacheKey = "search:result:" + version + ":" + sha256(criteria.cacheIdentity());
UnifiedSearchResponse cached = cacheService.getResult(cacheKey);
if (cached != null) return cached;
try {
    response = searchOpenSearch(criteria, vector, version);
} catch (RuntimeException error) {
    response = searchMySql(criteria, version);
}
```

版本进入 Key 后，增量事件或全量重建只需递增 `search:index:version`。旧缓存不再命中并按 2 分钟 TTL 自然删除，不需要危险的通配符批量删除。

### 5.2 BM25 与本地向量融合

```java
fuse(keywordPage.items(), 0.65D, sources, scores, matched);
fuse(vectorPage.items(), 0.35D, sources, scores, matched);

scores.merge(documentId, weight / (60D + rank + 1D), Double::sum);
```

BM25 查询字段权重为 `title^4 / authorName^2 / content`。向量由 `BAAI/bge-small-zh-v1.5` 在 FastAPI 本机生成。倒数排名融合不直接比较 BM25 和余弦分数，避免两种分数尺度不同造成排序漂移；0.65/0.35 表示关键词仍占主导。

### 5.3 索引消费者重新读取 MySQL

```java
case "SEARCH_POST_UPSERT" -> upsertOrDelete("POST", event.aggregateId());

SearchSourceDocument source = mapper.findPostDocument(id);
if (source == null) {
    indexClient.delete("POST", id);
    return;
}
indexClient.upsert(source, embedding(source));
```

RabbitMQ 消息不携带帖子正文和状态，避免重试旧消息把旧内容写回索引。消费者只拿 ID，再从 MySQL 读取最新状态；若已经删除、隐藏或失去公开资格，UPSERT 事件也会转为 DELETE。

### 5.4 文档 ID 保证重复消息幂等

```java
restClient.put()
    .uri("/{index}/_doc/{id}", indexName, type.toLowerCase() + ":" + businessId)
    .body(body)
    .retrieve().toBodilessEntity();
```

相同业务内容永远写相同 `_id`，RabbitMQ 至少一次投递不会创建两份索引文档。DELETE 同样忽略 404，重复撤回是安全的。

### 5.5 Lua 联想限流

```lua
local count = redis.call('INCR', KEYS[1])
if count == 1 then redis.call('PEXPIRE', KEYS[1], ARGV[1]) end
return count
```

Java 以 `search:suggest:rate:{userId}` 为 Key，一分钟最多 30 次。INCR 与首次 TTL 写入在 Redis 单线程 Lua 中原子完成，避免“计数成功但没设置过期”的永久锁死。

### 5.6 Redisson 全量重建锁

```java
RLock lock = redissonClient.getLock("search:index:rebuild");
boolean acquired = lock.tryLock(0, 30, TimeUnit.MINUTES);
if (!acquired) throw new IllegalStateException("已有搜索索引重建任务正在执行");
```

锁防止多实例同时删除并创建同一索引；MySQL `search_index_job.status` 仍保存最终事实。重建顺序为：读取公开投影 → 标记 RUNNING → 重建 Mapping → 清 Bloom → 逐条本地向量化/写入 → 校验失败数 → 完成任务 → 递增索引版本。任一文档失败时任务改为 `FAILED`，保存成功/失败计数及第一条安全错误摘要，并删除不完整索引，使查询回到权限等价的 MySQL 降级，不能把部分索引当成完整结果。

### 5.7 安全高亮

```vue
<mark v-if="part.matched">{{ part.text }}</mark>
<template v-else>{{ part.text }}</template>
```

`HighlightedText.vue` 先转义正则字符，再把文本切成命中/普通片段。模板插值由 Vue 做 HTML 转义，未使用 `v-html`，因此用户标题中的标签只能显示为文字。

### 5.8 OpenSearch 时间与超长正文边界

搜索 `RestClient` 显式使用 Spring Boot 管理的 `ObjectMapper`，`Instant` 以 ISO-8601 字符串写入 OpenSearch `date` 字段，禁止默认转换器生成小数秒时间戳。FastAPI 向量接口最多接收 10,000 个 Unicode 码点；Java 仅截断向量输入，OpenSearch 关键词字段和 MySQL 原文仍保持完整，中文和 emoji 不会在 UTF-16 代理项中间截断。

## 6. HTTP 接口完整契约

除 FastAPI 内部接口和公开健康检查外，以下接口都要求 `Authorization: Bearer <accessToken>`。普通搜索页允许 `USER/VERIFIED_SELLER`；管理重建只允许 `ADMIN`。

### 6.1 `GET /api/v1/search`

Path：无。Body：无。

| Query | 类型 | 必填 | 默认 | 约束/含义 |
|---|---|---:|---|---|
| `query` | String | 是 | 无 | 1～120 个 Unicode 字符；合并连续空格 |
| `type` | Enum | 否 | `ALL` | `ALL/POST/KNOWLEDGE/USER/TOPIC` |
| `petType` | String | 否 | 空 | 例如 `CAT/DOG/OTHER`；只影响有该字段的结果 |
| `category` | String | 否 | 空 | 例如 `FEEDING/HEALTH/VACCINE/BEHAVIOR/GROOMING` |
| `trustLevel` | String | 否 | 空 | 例如 `ADMIN_VERIFIED/COMMUNITY_REVIEWED` |
| `dateRange` | Enum | 否 | `ALL` | `ALL/LAST_7_DAYS/LAST_30_DAYS/LAST_YEAR` |
| `sort` | Enum | 否 | `RELEVANCE` | `RELEVANCE/LATEST` |
| `page` | Integer | 否 | 0 | 从 0 开始，不能为负 |
| `size` | Integer | 否 | 10 | 1～20；`ALL` 时每个分组最多返回 size 条 |

响应 `200 UnifiedSearchResponse`：

```json
{
  "query": "幼猫喂养",
  "type": "ALL",
  "page": 0,
  "size": 10,
  "total": 8,
  "backend": "OPENSEARCH",
  "degraded": false,
  "indexVersion": 3,
  "groups": [{
    "type": "KNOWLEDGE",
    "total": 2,
    "items": [{
      "id": "uuid", "type": "KNOWLEDGE", "title": "幼猫基础喂养",
      "snippet": "少量多餐……", "authorName": "资料来源", "avatarUrl": null,
      "sourceUrl": null, "routePath": "/app/chat?source=uuid",
      "petType": "CAT", "category": "FEEDING", "trustLevel": "ADMIN_VERIFIED",
      "publishedAt": "2026-08-26T03:00:00Z", "score": 0.018,
      "matchedFields": ["title", "content"]
    }]
  }]
}
```

`backend=MYSQL/degraded=true` 表示 OpenSearch 不可用，但返回值仍经过相同公开条件。错误：`400 INVALID_REQUEST`（空关键词、枚举/分页非法）、`401 AUTHENTICATION_REQUIRED`、`503 DATABASE_UNAVAILABLE`、`500 INTERNAL_ERROR`。

### 6.2 `GET /api/v1/search/suggestions`

Path/Body：无。Query：`query` 必填、1～120 字符；`limit` 可选，默认 8，服务限制到 1～10。响应 `200 SearchSuggestionResponse[]`，字段：`text`、`source=HISTORY/TRENDING/PUBLIC_CONTENT`。错误另有 `429 TOO_MANY_REQUESTS`（一分钟超过 30 次）。私人历史只返回当前用户自己的记录。

### 6.3 `GET /api/v1/search/history`

Path/Body：无。Query：`limit` 可选，默认 20，限制 1～50。响应 `200 SearchHistoryResponse[]`：`id/query/filtersJson/resultCount/searchCount/lastSearchedAt`。错误：`401`、`503`。

### 6.4 `DELETE /api/v1/search/history/{historyId}`

Path：`historyId` 必填 UUID 字符串；Query/Body：无。删除条件同时包含 `id` 和当前 `userId`，不能删除他人历史。响应 `204`，目标不存在也按幂等删除返回 204。错误：`401`、`503`。

### 6.5 `DELETE /api/v1/search/history`

Path/Query/Body：无。只清空当前用户历史，响应 `204`。错误：`401`、`503`。

### 6.6 `GET /api/v1/search/trending`

Path/Body：无。Query：`limit` 可选，默认 10，限制 1～20。响应 `200 SearchTrendingResponse[]`，字段：`query` 和 `score`。手机号、邮箱、少于 2 字或超过 30 字的查询不会进入 ZSet。Redis 不可用时返回空数组而不是伪造热词。

### 6.7 `POST /api/v1/admin/search/rebuild`

Path/Query/Body：无。仅 ADMIN。响应 `202 SearchIndexJobResponse`：`id/indexName/indexVersion/status/totalCount/indexedCount/failedCount/errorMessage/startedAt/completedAt/createdAt/updatedAt`。初始状态为 PENDING；同一事务写 `SEARCH_REBUILD_REQUESTED` Outbox。错误：`401`、`403 ACCESS_DENIED`、`503 DATABASE_UNAVAILABLE`。

### 6.8 `GET /api/v1/admin/search/rebuild/{jobId}`

Path：`jobId` 必填；Query/Body：无。仅 ADMIN。响应 `200 SearchIndexJobResponse`。错误：`400 INVALID_REQUEST`（任务不存在）、`401`、`403`、`503`。当前沿用参数错误契约，后续若统一资源语义可增加专用 404 异常。

### 6.9 `POST /api/v1/knowledge/search/embed`（FastAPI 内部）

Path/Query：无。Body：

```json
{ "text": "幼猫少量多餐", "mode": "QUERY" }
```

`text` 必填 1～10000 字符；`mode=QUERY/DOCUMENT`。响应 `200`：`embedding` 浮点数组、`embedding_model`、`dimensions`。Java 只能通过 `KnowledgeAiClient` 调用；浏览器不直连。错误：FastAPI `422` 参数校验错误、`503` 本地模型不可用。

### 6.10 `GET /api/v1/system/health`

Path/Query/Body：无，公开。响应 `200` 新增 `opensearch: UP/DOWN`，并保留 `businessService/aiService/database/redis/rabbitmq/minio`。该接口只探活，不返回连接串、密码或索引内容。

## 7. Redis 数据结构

| Key | 类型 | 示例值 | TTL/清理 | 写入/读取 | 故障与回源 |
|---|---|---|---|---|---|
| `search:index:version` | String | `3` | 无固定 TTL | 索引消费者写；搜索服务读 | 丢失从 1 开始，只降低缓存命中 |
| `search:result:{version}:{sha256}` | String JSON | 分组搜索响应 | 默认 2 分钟 | 搜索服务读写 | 未命中查 OpenSearch/MySQL |
| `search:suggestion:{sha256}` | Hash | `items/generatedAt` | 5 分钟 | 联想服务读写公开标题候选 | 未命中回源 MySQL 公开标题 |
| `search:trending` | ZSet | `幼猫喂养 → 12` | 7 天；最多 200 | 搜索写；页面读 | 故障返回空趋势 |
| `search:suggest:rate:{userId}` | String | `7` | 1 分钟 | Lua 原子 INCR/PEXPIRE | Redis 故障放行公开联想 |
| `search:public:id:bloom` | Bloom | `POST:uuid` | 全量重建 | 索引服务维护 | 只能判空提示，MySQL 最终确认 |
| `search:public:id:bloom:ready` | String | `1` | 重建开始删除、完成写入 | DELETE 事件读 | 标记缺失时放行 OpenSearch 删除，绝不误拦 |
| `search:index:rebuild` | Redisson Lock | 锁所有权 | 租约 30 分钟 | 重建服务 | MySQL 任务表保存事实 |

缓存 Key 不包含用户身份，因为结果都是统一公开内容；私人历史从不进入共享结果缓存。索引版本变化使旧缓存自然失效。

## 8. RabbitMQ 与 Outbox 事件

交换机 `pet.search.events`，队列 `pet.search.index`，Routing Key `search.index`。新增事件：

| 事件 | 业务来源 | 消费结果 |
|---|---|---|
| `SEARCH_POST_UPSERT/DELETE` | 发布、已发布编辑、作者删除、管理员隐藏 | 查最新公开状态后 PUT/DELETE |
| `SEARCH_KNOWLEDGE_UPSERT/DELETE` | 审核发布、作者撤回 | 查 READY/APPROVED/授权/有效期后 PUT/DELETE |
| `SEARCH_USER_UPSERT` | 修改公开资料、角色或状态 | 非 ACTIVE 或非普通公开角色会转为 DELETE |
| `SEARCH_TOPIC_UPSERT/DELETE` | 话题状态变化（服务已预留） | 查 ACTIVE 后 PUT/DELETE |
| `SEARCH_REBUILD_REQUESTED` | 管理员重建 | Redisson 加锁后从 MySQL 全量重建 |

`OutboxPublisher` 按 `aggregate_type` 路由：`KNOWLEDGE_SUBMISSION` 去知识队列，`SEARCH_*` 去搜索队列，其余去社区队列。失败使用原有指数退避，不删除 Outbox 事实。

## 9. 前端页面与状态

路由：`/app/search`；角色：`USER/VERIFIED_SELLER`。导航在桌面端与移动端都增加“搜索”。

- 左栏：当前用户搜索历史，可点击恢复、单删或清空。

- 右栏：Redis 脱敏趋势和隐私说明。
- 加载：显示“正在检索公开内容”；空查询提示输入示例；零结果提示减少筛选；错误显示原因和重试按钮。
- 降级：`degraded=true` 时显示“OpenSearch 暂不可用，当前使用 MySQL 安全降级”。
- 页面外壳固定为 `100dvh`，各栏内部滚动；移动端改为单列并保留底部导航。
- API 状态来自 `api/search.ts`；路由 Query 是查询状态事实源，不额外把搜索条件写入 localStorage。

管理端 `/manage/system` 新增索引面板：点击“重建全部索引”调用 POST，之后每 1.5 秒 GET 任务，直到 COMPLETED/FAILED。

```properties
OPENSEARCH_ENDPOINT=http://<虚拟机IP>:9201
OPENSEARCH_INDEX=pet_assistant_public_v1
OPENSEARCH_CONNECT_TIMEOUT=3s
OPENSEARCH_READ_TIMEOUT=10s
```

虚拟机 Docker 端口必须使用 `9201:9200` 或 `0.0.0.0:9201:9200`。`127.0.0.1:9201:9200` 只允许虚拟机自身访问，Windows 无法通过虚拟机 IP 连接。

按原顺序启动 FastAPI 8000、Spring Boot 8080、Vue 5173。首次索引：以 ADMIN 登录 → 管理端 → 系统状态 → “重建全部索引”。也可调用 `POST /api/v1/admin/search/rebuild` 并轮询返回的任务 ID。

若本机暂时没有 OpenSearch：

```properties
OPENSEARCH_ENABLED=false
```

搜索接口仍可用并返回 `backend=MYSQL/degraded=true`；增量索引消费者可临时设置 `SEARCH_RABBIT_LISTENER_ENABLED=false`。恢复 OpenSearch 后重新启用并执行一次全量重建。

## 12. 常见问题

### 搜索页一直显示 MySQL 降级

检查 `.env` 中的 `OPENSEARCH_ENDPOINT`、`OPENSEARCH_ENABLED` 和虚拟机端口监听地址，再到管理端重建索引。OpenSearch 空索引不会从业务表自动猜测历史数据，必须执行全量重建。

### 新发布内容暂时搜不到

检查 RabbitMQ 5672、`pet.search.index` 队列、`integration_outbox` 的 `status/attempts/next_attempt_at`，以及 FastAPI 8000 本地 embedding。索引是最终一致，不应在发布事务里同步等待向量化。

### 重建任务显示失败

查看管理端 `errorMessage`、`indexedCount/failedCount` 和 Java 日志中的文档类型/ID。任务只要有一条失败就标记 `FAILED` 并删除不完整索引；修复依赖后重新重建即可。向量输入超过 10,000 个 Unicode 码点时 Java 会安全截断，但 MySQL 与关键词索引中的原文不截断。

### 为什么 Redis 停止仍能搜索

Redis 只负责缓存、趋势、限流、Bloom 和锁，不是公开内容事实。普通查询可继续访问 OpenSearch/MySQL；全量重建需要 Redisson Lock，因此应先恢复 Redis。

### 为什么知识数量比数据库文档少

搜索只包含 READY、APPROVED、未撤回且未过期的文档。投稿、驳回版本、撤回资料和未审核文档故意不可见。
