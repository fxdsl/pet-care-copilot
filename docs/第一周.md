# 第一周：需求、架构与工程骨架

> 历史说明：第一周曾以 PostgreSQL/pgvector 作为后续占位方案；第二周根据实际开发环境改用 MySQL 作为业务数据库。当前配置和启动方式请以[第二周开发文档](第二周.md)为准。

## 1. 本周目标

第一周不追求“回答得聪明”，而是先建立一个边界清楚、能够继续扩展的项目地基。本周完成后应当能够：

1. 理解产品为谁服务、解决什么问题，以及第一版不做什么。
2. 分别启动 Vue、Spring Boot、FastAPI 三个工程。
3. 从网页发送问题，经 Spring Boot 转发给 FastAPI，再把结果显示在网页上。
4. 通过自动化测试确认两个后端服务的基本行为。
5. 为第二周的数据库与知识库工作保留明确的扩展位置。

## 2. 产品需求

### 2.1 目标用户

- 第一次养猫或养狗、缺少系统知识的人。
- 遇到日常喂养、清洁、行为、疫苗、驱虫等问题，希望快速获得说明的人。

### 2.2 要解决的问题

- 养宠知识分散，查找成本高。
- 搜索结果质量参差不齐，用户难以判断来源是否可靠。
- 单轮搜索无法结合宠物年龄、体重、品种等上下文继续追问。

### 2.3 第一版核心功能

后续八周版本的最小产品范围如下：

| 功能 | 用户价值 | 计划阶段 |
|---|---|---|
| 宠物知识问答 | 用自然语言获取养护建议 | 第 3～4 周 |
| 答案来源引用 | 用户能够核对依据 | 第 3～4 周 |
| 多轮会话与历史记录 | 围绕同一个问题继续追问 | 第 4 周 |
| 检索质量优化 | 减少无关资料和模型幻觉 | 第 5 周 |
| Agent 工具调用 | 处理喂养量计算等结构化任务 | 第 6 周 |
| 流式回答 | 降低用户等待感 | 第 7 周 |

### 2.4 本阶段不包含的内容

- 不提供疾病确诊、处方、用药剂量或替代兽医诊疗的结论。
- 暂不支持猫狗以外的宠物。
- 暂不实现支付、商城、社区、在线问诊。
- 第一周不连接大模型，也不产生真正的 RAG 回答。
- 第一周的数据库和 Redis 仅提供基础设施配置，业务代码尚未连接。

### 2.5 安全边界

- 页面必须持续展示“不能替代临床诊断”的提示。
- 遇到呼吸困难、持续抽搐、严重出血、误食毒物等紧急描述时，正式版本应优先建议立即联系兽医。
- 正式回答应附知识来源；检索不到可靠材料时，模型应明确说明不确定，而不是编造。
- 用户输入、日志和模型上下文中不应保存不必要的个人敏感信息。

## 3. 系统架构

### 3.1 为什么拆成三个服务

```text
┌─────────────────┐       HTTP/JSON       ┌────────────────────┐
│ Vue 3 前端       │ ───────────────────▶ │ Spring Boot 业务层   │
│ localhost:5173  │ ◀─────────────────── │ localhost:8080      │
└─────────────────┘                       └─────────┬──────────┘
                                                   │ WebClient
                                                   │ HTTP/JSON
                                                   ▼
                                         ┌────────────────────┐
                                         │ FastAPI AI 层       │
                                         │ localhost:8000      │
                                         └────────────────────┘

第二周开始接入：PostgreSQL + pgvector、Redis
```

各层只承担一类职责：

- **Vue 3 前端**：收集问题、展示会话和来源，不直接访问 AI 服务。
- **Spring Boot 业务层**：作为前端唯一入口，后续负责用户、会话、消息、权限、限流和 AI 服务编排。
- **FastAPI AI 层**：后续负责文档切分、检索、提示词、模型调用和 Agent，不管理普通业务数据。
- **PostgreSQL + pgvector**：保存用户/会话等关系数据，以及文档向量。
- **Redis**：后续用于缓存、限流、临时状态和分布式协调。

这样拆分的好处是：AI 技术迭代时主要修改 Python 服务，用户和会话业务迭代时主要修改 Java 服务，前端不会依赖某一个模型厂商。

FastAPI 因此没有为浏览器开放跨域访问；这是代码层面对“前端不能绕过业务层”的约束，而不只是团队约定。

### 3.2 一次请求如何流动

以“幼猫一天应该喂几次？”为例：

1. 用户在 Vue 页面点击“发送”。
2. Vue 调用 `POST http://localhost:8080/api/v1/chat/preview`。
3. Spring Boot 校验问题非空且不超过 2,000 个字符。
4. Spring Boot 使用非阻塞 `WebClient` 调用 FastAPI 的 `/api/v1/ai/chat`。
5. FastAPI 返回第一周占位回答。
6. Spring Boot 保持统一的前端响应结构并返回结果。
7. Vue 把回答追加到会话区域。

正式 RAG 上线后，第 4 步的前后端契约不需要变化，只需替换 FastAPI 内部的 `ChatService` 实现。

## 6. 本地启动步骤

### 6.1 环境要求

- JDK 17 或更高版本
- Maven 3.6.3 或更高版本
- Node.js 20 或更高版本
- Python 3.11 或更高版本
- Docker Desktop（第二周使用，本周不是必需）

本项目在 2026-08-13 选择仍受支持的稳定分支：Spring Boot `3.5.x`、FastAPI `0.140.x`、Vue `3.5.x`、Vite `8.2.x`。Java 服务暂不直接跨到 Spring Boot 4，以免第一周同时承担 Jakarta/框架主版本迁移风险；`3.5.x` 仍是官方列出的稳定版本。

### 6.2 启动 FastAPI

在项目根目录执行：

```powershell
cd ai-service
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

访问 `http://localhost:8000/docs` 可以使用 FastAPI 自动生成的交互式接口文档。

### 6.3 启动 Spring Boot

新开一个终端：

```powershell
cd backend\business-service
mvn -s .mvn/settings.xml spring-boot:run
```

如果 FastAPI 不在默认的 `8000` 端口，可先设置：

```powershell
$env:AI_SERVICE_BASE_URL = "http://localhost:新的端口"
mvn -s .mvn/settings.xml spring-boot:run
```

### 6.4 启动 Vue

再开一个终端：

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

使用 `npm.cmd` 是为了避开某些 Windows 机器默认禁止执行 `npm.ps1` 的问题。访问 `http://localhost:5173` 即可看到页面。

## 10. 核心代码讲解（后补）

> 状态说明：第一周的占位接口已在后续周删除。下面结合当前最终代码解释第一周确定的“三端解耦”原则，不代表要恢复旧占位实现。

### 10.1 Java Controller 为什么必须保持很薄

代码位置：`backend/business-service/src/main/java/com/petassistant/business/controller/ChatController.java`。

```java
@RestController
@RequestMapping("/api/v1/chat")
public class ChatController {
    private final ChatService chatService;

    public ChatController(ChatService chatService) {
        this.chatService = chatService;
    }

    @PostMapping("/preview")
    public ChatResponse preview(@Valid @RequestBody ChatRequest request) {
        return chatService.answer(request);
    }
}
```

这段代码只完成三件事：注册 URL、触发 Bean Validation、把请求交给 `ChatService`。它不读取 MySQL、不拼接模型 Prompt，也不处理 Redis。这样以后更换 AI 实现时，HTTP 契约不必跟着业务算法一起变化。

调试时可以先在 `preview()` 打断点：如果断点未进入，问题在 Vue 地址、跨域或 8080 服务；如果已经进入而响应失败，继续进入 `ChatService.answer()`。

### 10.2 Java 如何隔离 FastAPI 协议

代码位置：`backend/business-service/src/main/java/com/petassistant/business/client/AiServiceClient.java` 的 `answer()`。

```java
public AiRagResponse answer(AiRagRequest request) {
    try {
        AiRagResponse response = aiRestClient.post()
                .uri("/api/v1/rag/answer")
                .body(request)
                .retrieve()
                .body(AiRagResponse.class);
        if (response == null) {
            throw new IllegalStateException("AI 服务返回空响应");
        }
        return response;
    } catch (Exception error) {
        throw new AiServiceUnavailableException(error);
    }
}
```

`Client` 层只负责内部 HTTP 契约和异常转换。`ChatService` 不需要知道 FastAPI 的地址、连接方式或 HTTP 客户端配置。FastAPI 超时、无法连接或返回非 2xx 时，统一转换成 `AiServiceUnavailableException`，再由全局异常处理返回浏览器可理解的 502。

调试时重点观察 `request.candidates()`、`request.history()` 和返回的 `routingReason`，不要在日志中打印 API Key。

### 10.3 FastAPI 路由和算法为什么分开

代码位置：`ai-service/app/api/routes.py`。

```python
@rag_router.post("/answer", response_model=RagResponse)
def answer_with_rag(
    request: RagRequest,
    service: RagService = Depends(get_rag_service),
) -> RagResponse:
    """对 Java 提供的候选分块执行 Top-K 检索并生成带来源答案。"""
    return service.answer(request)
```

路由层负责 JSON 校验和响应模型，真正算法在 `RagService`。`Depends` 负责注入服务，使自动化测试可以替换 embedding 或模型调用。第一周所说的“AI 能力边界”最终就落实为这个结构。

### 10.4 Vue 为什么只访问 Java

代码位置：`frontend/src/App.vue` 的 `submitQuestion()`。

```ts
const response = await sendQuestion({
  question: content,
  conversationId: conversationId.value,
  petProfileId: selectedProfileId.value || undefined,
  petType: fallbackPetType.value || undefined,
  category: selectedCategory.value || undefined,
})
conversationId.value = response.conversationId
messages.value.push({
  role: 'assistant',
  content: response.answer,
  sources: response.sources,
  routingReason: response.routingReason,
})
```

浏览器只认识 Spring Boot 的业务接口，不直接调用 FastAPI。这样 API Key、候选知识向量和内部 Prompt 都不会暴露给浏览器。`conversationId` 使用 Java 返回值，避免前端自行生成无效会话。

完整调试顺序是：`submitQuestion()` → `ChatController.preview()` → `ChatService.answer()` → `AiServiceClient.answer()` → FastAPI `answer_with_rag()`。

## 11. 第一周接口参数字典（后补）

> 本节记录第一周当时的占位契约。`POST /api/v1/ai/chat` 已在第五周删除，当前内部回答接口以第五周参数字典为准。

| `status` | string | 否 | `UP` 表示 FastAPI 进程可响应 |
| `version` | string | 否 | 第一周为 `0.1.0` |

第一周示例响应：

```json
{"service":"pet-assistant-ai-service","status":"UP","version":"0.1.0"}
```

第五周已扩展 `embedding_model`、`answer_mode`、`llm_provider`、`llm_model`，详见第五周接口参数字典。

### 11.2 `POST /api/v1/ai/chat`（历史接口，已删除）

调用方向：Spring Boot → FastAPI。Path、Query 参数无；请求头为 `Content-Type: application/json`。

| Body 字段 | 类型 | 必填 | 约束/默认值 | 含义 |
|---|---|---|---|---|
| `question` | string | 是 | 非空，最多 2000 字符 | 用户问题 |
| `conversation_id` | string | 否 | 默认 `null` | Java 转发的可选会话编号 |

| 响应字段 | 类型 | 可空 | 含义 |
|---|---|---|---|
| `answer` | string | 否 | 第一周占位回答 |
| `conversation_id` | string | 是 | 原样返回请求中的会话编号 |
| `sources` | array | 否 | 第一周固定为空数组 |
| `stage` | string | 否 | 固定 `week-1-placeholder` |

成功状态码为 `200`；JSON 缺失或校验失败时 FastAPI 返回 `422`。

### 11.3 `POST /api/v1/chat/preview`（第一周外部契约）

调用方向：Vue → Spring Boot。Path、Query 参数无。

| Body 字段 | 类型 | 必填 | 约束/默认值 | 含义 |
|---|---|---|---|---|
| `question` | string | 是 | 非空，最多 2000 字符 | 用户输入的问题 |
| `conversationId` | string | 否 | 默认 `null` | 第一周只透传，不自动建会话 |

| 响应字段 | 类型 | 可空 | 含义 |
|---|---|---|---|
| `answer` | string | 否 | FastAPI 占位回答 |
| `conversationId` | string | 是 | 对外使用驼峰命名 |
| `sources` | array | 否 | 第一周为空数组 |
| `stage` | string | 否 | `week-1-placeholder` |

成功状态码为 `200`。常见错误：`400 INVALID_REQUEST`（问题为空）和 `502 AI_SERVICE_UNAVAILABLE`（8000 端口不可访问）。第五周该地址的字段已增加档案、过滤、模型、路由与页码，见第五周接口参数字典。

### 11.4 `GET /api/v1/system/health`（第一周）

调用方向：浏览器或开发者 → Spring Boot。Path、Query、Body 均无，成功状态码为 `200`。

| 响应字段 | 类型 | 可空 | 含义 |
|---|---|---|---|
| `businessService` | string | 否 | Java 自身状态，正常为 `UP` |
| `aiService` | string | 否 | Java 探测 FastAPI 的结果：`UP`/`DOWN` |

第二周以后增加了 `database` 和 `redis`。健康接口即使某个依赖为 `DOWN` 仍返回 `200`，调用方应读取字段，而不是只看 HTTP 状态。

### 11.5 第一周统一错误字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `code` | string | 稳定业务错误码，例如 `INVALID_REQUEST` |
| `message` | string | 可直接展示给用户的中文说明 |
| `timestamp` | ISO-8601 string | 错误发生时间 |
